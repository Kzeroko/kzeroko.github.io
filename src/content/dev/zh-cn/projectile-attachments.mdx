`AttachmentAPI`管理环绕施法者的弹体组，`ProjectilePatternAPI`通过既有的`MagicProjectileAPI`投递路径组合延迟连射与弹雨。美术、伤害策略、目标筛选、召唤位置和发射时序分别配置。

## 它做什么

种族能力与法术通过不同的附着组并存。每组各自设置容量、合并规则与触发方式，类别用于查询相关组。`SpellCatalog`在`spell.instance.catalog`中注册配置式法术，共用基类为`ConfiguredSpell`。既有法术标识符保持不变。

奥术连射（`isekaiexpansion:arcane_volley`）在24刻（1.2秒）引导中投递12枚魔法飞弹。每次施法生成一个随机种子，在施法者身后的半径2.4格范围内按径向分布弹体。每枚等待5刻（0.25秒）后飞出，速度为×2.5，每刻最多转向28度；每发伤害倍率减少0.025，最后一发为×0.725，配置下限为×0.65。松开引导后不再产生新的付费投递，已投递的弹体继续飞行。完整引导的8秒冷却使用与引导光束相同的按持续时间缩放规则。

陨星雨（`isekaiexpansion:meteor_rain`）复用流星弹体、召唤前奏、入场生长和命中特效。半径4格的平面魔法阵位于目标上方16格，并按偏离垂直方向45度的落线计算水平偏移；上方受阻时最低可降至6格。成形20刻（1秒）后发射12枚弹体，间隔3刻（0.15秒）。伤害归属于陨星雨自身。

## 运行时模型

服务端管理附着成员、瞄准点与释放时间。发射请求只预约选中的弹体；每枚在自己的绝对发射刻到达前保持附着，随后才脱离、将飞行年龄归零并显式同步速度。其他弹体保留原槽位。初始延迟与同组发射间隔由配置决定，间隔0表示所选批次同时释放。重复挥动回调不会二次预约已排队弹体。附着时间不计入飞行寿命，已预约弹体即使超过备弹寿命，也会完成释放时序。

主手空手或持任意物品挥动，以及Better Combat武器挥动，均调用`AttachmentAPI.swing`。`EntityUtil.spellCursor`通过地形、法术关系和可见性确定准星指向的有效实体或位置，并应用命中策略的额外筛选。距离取配置追踪范围与“15格加魔剑感知”的较大值，上限64格。若选中敌人，弹体可在起飞后跟随该目标；否则飞向挥动时记录的准星位置。备弹不会自行搜索或攻击附近敌人，丢失已选目标后也不再搜索替代目标。

妖狐狐火使用同一附着组规则。已有狐火但没有有效目标时，再次激活会在扣除能量与冷却前返回失败。一个或两个敌人也能通过轮流分配接收全部狐火。实体命中必须实际造成伤害才消耗狐火；受保护目标不会吸引它。重塑狐火通过与召唤相同的容量和生成检查追加一枚。

`AttachablePositioner`为逻辑和表现提供同一套姿态计算。模型、精灵图与`EntityEffekAPI`在附着期间采样持有者插值后的位置、偏航角和俯仰角；偏航跨越角度边界时按最短方向转动。抬头或低头不会让阵列位置上下绕转，但弹体朝向会跟随瞄准方向。环形阵列共用几何计算和连续的世界时间相位。渲染不累计位置滤波状态，也不搜索目标。

`EntityEffekAPI`在备弹和预约等待期间移动、旋转整个原生特效。附着状态改变时，`WORLD_WAKE`结束备弹模拟，以单位基础坐标系和原生世界坐标的位置、旋转、缩放接口开始飞行，使直接发射与倾斜弹雨使用一致的创作朝向和拖尾继承规则。`RIGID`在整个飞行阶段保持完整特效随动。飞行朝向在客户端相邻逻辑刻的速度之间插值，未改变的变换不会重复提交。

## 约定

### 附着组

`AttachmentAPI.Set`需要组ID、类别、容量、合并规则和触发方式。单组容量为1–64，拥有者的总附着数量也限制为64。类别只用于查询，不互相排斥。

| 规则 | 行为 |
| --- | --- |
| `REPLACE` | 先生成请求的新组，成功后只移除同组旧成员；生成失败保留旧组。 |
| `APPEND` | 在单组与拥有者容量内追加请求数量。 |
| `REFILL` | 仅补足到请求总数，同样受容量限制。 |
| `MANUAL` | 只通过显式API调用释放。 |
| `SWING` | 主手空手或持任意物品挥动时，预约向准星位置释放。 |



`AttachmentAPI.Profile`还提供数量、阵列样式、间距、附着和飞行寿命、速度、转向角、追踪范围、初始延迟、弹体间隔、阵列自转与命中ID。寿命使用正整数刻；间距0.1–16格，速度大于0且不超过每刻16格，转向每刻0–180度，范围0–64格。初始延迟0–1200刻（0–60秒），间隔0–100刻（0–5秒），自转每刻−360–360度。不合法的配置在生成前抛出异常。

火球使用实体 ID `isekaiexpansion:fireball`，不为已退役的原型 ID 提供别名。

当前存档在`Attachment`复合标签中保存组信息、阶段年龄、阵列槽位与运动参数，其中`Launch`保存时序、绝对释放刻、瞄准点与可选目标UUID。这是实体存档，不是数据包编写接口。已移除的自动触发方式、脱离后的等待状态与旧存档格式均不保留兼容别名；无效附着状态会被丢弃。

### 飞行、放置与弹雨

`MagicProjectileAPI.Flight`提供速度倍率、转向角、追踪范围、等待刻数、伤害倍率与尺寸。速度和伤害倍率大于0且不超过×8，转向0–180度，范围0–64格，等待0–100刻（0–5秒），尺寸为×0.25–×3。尺寸同时放大弹体碰撞箱、原生特效大小、命中表现与溅射半径。`Flight.tuned`以`SpellTuning`的速度、威力与规模构建法术自身的飞行；`compose`把弹幕每发的飞行乘以同样三项。`Fan(count, degrees)`把一次直接发射复制为1–8发，围绕瞄准方向沿水平弧线展开，相邻间隔0–45度。不带飞行参数的直接发射使用弹体调校值。

`MagicProjectileAPI.Placement`提供有符号的前后、左右和上下偏移，以及搜索半径、高度和步长。负前向偏移将魔法阵放在施法者身后。有界搜索最多检查 512 个候选位置，核对已加载空间、遮挡和既有魔法阵间距，找不到位置返回false，不会退回脚下重叠召唤。

`ProjectilePatternAPI.Volley`数量为1–64，间隔1–100刻，等待0–100刻，阵列半径0.5–4格，还接收飞行速度、转向、范围与逐发伤害衰减及下限。每一发调用一次`volleyShot`，传入弹体序号、本次施法的总发数、本次施法固定使用的种子及其`SpellTuning`；序号超出总发数时不发射，调整值会叠加到每发的飞行上。奥术连射的术式把6、12、24或36发分摊到12次已付费投递中，伤害衰减仍按弹体序号计算，直至下限。内部`backGate`采样器在施法者身后组合角度间距和有界径向抖动，不使用逐排上升计数或重试循环；放置检查仍会拒绝遮挡和未加载空间。

`ProjectilePatternAPI.Rain`需要唯一逻辑ID、直接弹体配置、魔法阵设计、半径、首选与最低高度、角度、数量、间隔、成形及淡出时间。半径大于0且不超过8格，高度2–48格，最低高度不得超过首选高度。角度为偏离垂直方向0–60度，0表示垂直下落。数量1–128，间隔1–100刻（0.05–5秒），成形和淡出均为1–100刻（0.05–5秒）。

`RainCast(ammunition, count, radius, tuning)`决定一次施法的形态。数量1–128与大于0且不超过8格的半径会替换配置中的值；各发依次轮流使用`ammunition`中的弹体，列表为空时使用弹雨自身的弹体，调整值叠加到飞行上。发射空间按调整尺寸后弹雨自身弹体与弹药中最宽者计算。弹药需通过`registerAmmunition`注册，存档中的弹雨才能恢复。魔法阵加载时若存档逻辑状态无效（包括未知弹药），会记录警告并移除该法阵。

放置以半格为步长向下尝试。整个发射空间必须位于已加载区域和世界边界内且无阻挡，中心路径需畅通，落线长度必须在弹体射程内。最低高度仍不可用则施法失败。圆盘采样用平方根半径与均匀角度，在常数时间内完成，并为弹体宽度预留边距。弹体平行下落，使目标平面的覆盖范围与圆盘一致。生成时被新放置障碍物挡住的那一发直接跳过，不进行重试循环；飞行仍受地形阻挡。

目录弹体使用扫掠实体碰撞，而非只检查单点。风刃、水刃与流星的实体宽度为0.8格，雷枪与灵魂箭为0.6格，其余目录弹体为0.45格。地形碰撞仍使用既有方块射线。`MagicProjectileAPI.ImpactProfile.splashRadius`为0时结算直接伤害，大于0且不超过8格时只结算命中范围伤害，且仅允许单次命中配置。实际半径为配置半径乘以弹体尺寸，上限8格。流星及其召唤、连射、弹雨变体采用1.75格半径。接触实体或地形时只产生一次星界爆发，检查关系与遮挡，不再额外结算直接命中伤害。火球术、火球术·召唤与绯焰星陨通过`FireballSpell.impacts`共用1.75格半径的撞击范围结算；每枚弹体对每个符合条件的目标只施加一次各自的火焰伤害与引燃。

### 元素备弹与法阵光束

星辉连奏（`isekaiexpansion:shooting_star_volley`）复用奥术连射的逐次付费投送模式，使用流星裂隙与弹体。绯焰星陨（`isekaiexpansion:fireball_rain`）复用陨星雨的布置与时序，沿用火球的出现、飞行与各表面命中特效。

雷枪、冰针和炎矢各提供一个带两种式样的 `_attach` 法术：刻印增加1发，三重增加3发。两种式样共用对应元素的 `_arsenal` 集合，容量为3，合并规则为`APPEND`，触发方式为`SWING`，不同元素可以共存。`AttachmentAPI.available`同时计算持有者的总额度，只有该式样的每一发都有槽位时才会投送，生成失败会回滚新批次。备弹保留600刻（30秒）；挥动后第一发等待3刻（0.15秒），其余按2刻（0.1秒）间隔释放。元素备弹、狐火与幽魂剑的每次伤害均绕过受击冷却，同时命中时仍各自结算。

其他法术伤害带有`SpellStrikes`记录的打击：每个弹体实体在整段飞行中是同一次打击，射线与同步施法各开启一次新打击。若施法者上一次对该目标造成的法术命中来自另一次打击，这次命中会穿过目标的受击冷却，因此大规模施法能全额命中。同一次打击再次命中、不属于任何打击的伤害和非法术伤害仍遵守受击冷却。

`CircleBeamAPI.Profile`组合光束配置、法阵表现、有界位置搜索、展开、脉冲间隔、退场及`Sweep(arcDegrees, degreesPerTick)`。横扫角为0–120度，速度为每刻0.05–30度。横扫时长为`max(1, ceil(arcDegrees / degreesPerTick))`，活动时长再加光束蓄力、延伸与最后1刻。展开为0–200刻（0–10秒），退场为0–100刻（0–5秒），计算出的活动时长不能超过光束最大寿命。脉冲间隔至少为1刻，不能超过光束心跳期限。无效配置抛出异常，每份配置需在施法前注册一次。

`CircleBeamAPI.Pattern(profile, circles, arc, pace, stage, modulation)`决定一次施法的形态：布置1–4座该配置的法阵（`MAX_CIRCLES`）。横扫角0–120度替换每座法阵的横扫角。节奏×0.25–×4用来除原设横扫刻数，四舍五入且至少1刻，每刻至少0.05度，因此横扫角不变，只改变时长。法阵站在站位所在的施法者身后一排，间距为`2 × 0.72 × scale + 0.5`格，居中者最多抬高0.5格；单独施放时保持原设位置。施法者左侧的法阵保持原设的从左到右横扫，其余镜像，使光束向瞄准点收拢。同一持有者64格内只允许一次进行中的该类施法，但同一术式施法的法阵共享分组，可以并排。找不到位置的法阵会被跳过，至少生成一座即视为施法成功。`ChannelBeamAPI.Modulation(scale, potency)`把碰撞半径与表现乘以×0.25–×3，把伤害乘以大于0且不超过×8的威力；引导脉冲也接受同样的调制。

星界终曲（`isekaiexpansion:astral_sweep`）一次付费后布置`BEAM_FOCUS`法阵：展开20刻（1秒）、活动97刻（4.85秒）、退场15刻（0.75秒）。光束蓄力12刻（0.6秒）、延伸4刻（0.2秒），随后每5刻（0.25秒）接收一次伤害脉冲。每次脉冲采用`4 + 0.7P`，`P`为应用共享伤害修正前的星界法术强度。蓄力时追踪目标，横扫开始时锁定瞄准点，以每刻0.6度横扫48度，持续80刻（4秒）。横扫始终保持固定俯仰角，向地面瞄准时也不继续下压或回扫。射程40格，碰撞半径2.1格，初始位置相对眼部向后0.8格、侧移1.8格、上移1.4格。同一持有者附近仅允许一次进行中的法阵光束施法，无论它布置了几座法阵；持有者离开64格范围或失效时结束。

`ChannelBeamAPI.Source`可把发射点绑定到实体、追踪目标实体，或每个服务端tick调用自定义`Aim`，返回世界坐标瞄准点。`CircleBeams`在蓄力期间采样已选目标，丢失目标后保留最后位置，并保存横扫使用的锁定瞄准点。每个法阵拥有独立光束槽。共享光束追踪命中地形前的所有有效实体，仅由地形截停，全部原生发射器使用同一同步方向与长度。地形表现逐刻刷新，实体相交与遮挡检查只在实际伤害投送时运行，无需在不结算伤害的显示刻扫描候选。星界彗流采用1.4的碰撞半径，换算原生input 1时保持1.5的创作半径，使碰撞与视觉宽度一起加倍。实体追踪按光束厚度抬高瞄准点，避免提前撞到目标脚下地面；准星地面瞄准仍使用准确落点。

伊芙莉娜的 `NpcBeamActions.channel` 使用同一光束配置和实时实体目标。`NpcAction.onExecuteTick` 管理重复投送，返回 false 会中断动作。她的星界彗流施法阶段为 24 ticks（1.2 秒），执行窗口为 120 ticks（6 秒），脉冲间隔为 5 ticks（0.25 秒），冷却为 360 ticks（18 秒），起手距离至少为 6 格。动作复用现有蓄力动画，以有界转速跟随移动；停止、目标失效或打断均会释放光束。NPC 动作使用自身冷却与执行生命周期，不扣除玩家的星能账户。

伊芙莉娜在全部14个受支持法术学派中的基础强度均为22，包括治疗、光、暗、血，以及按法术强度结算的物理近战学派。`NpcCombatAttributes.addSpellPower`通过内部的`IsekaiSpellSchools.all`取得完整学派列表；普通近战攻击伤害仍为5，生命上限仍为400。读取实体存档时会重新应用这套固定基础值，并保留装备与状态修正。

## 扩展

直接弹体与附着配置使用相同命中ID，即可复用原生美术、伤害与飞行入场。下列方法返回成功附着的数量：

```java
static int attachSpell(LivingEntity caster,
                       MagicProjectileAPI.DirectProfile projectile,
                       AttachmentAPI.Profile attachment) {
    return MagicProjectileAPI.attach(caster, projectile, attachment).size();
}
```

在公共初始化阶段注册一次命中策略和弹雨逻辑，用`AttachmentAPI.members`、`category`和`launch`实现指定组的玩法。带数量和时序的重载`launch(owner, set, target, count, delayTicks, intervalTicks)`最多预约`count`发，间隔0表示同时释放；返回值是接受预约的数量，发射回调也在接受预约时执行。成员在自己的预定刻到达前保持附着。客户端施法法阵通过`SpellClientData.registerCircle`注册，没有注册便不显示附着施法法阵。

## 验证

运行`gradlew.bat compileJava test assembleLanguageFiles`。回归测试覆盖发射预约、交错与同时释放、瞄准点和队列存档、合并数量、带种子的身后布置、圆盘采样、伤害衰减、有界转向与固定俯仰横扫。姿态测试覆盖不受帧数影响的采样、偏航跨界、完整原生特效旋转与世界坐标飞行变换；这些检查不运行Minecraft世界。

在游戏中让狐火环绕超过8秒，再测试零个、一个、两个和多个敌人，以及友方与受保护NPC，确认静置备弹不会自行发射。分别空手、持普通物品和Better Combat武器挥动，瞄准敌人、地形与天空。确认每发在预定释放前保持附着，其他弹体不换位，同时命中的每枚都能造成伤害。保存并重载已预约批次；将狐火能力激活的扣费检查与准星挥动分开验证。提前结束各类连射，检查按时长缩放的冷却、身后径向分布，以及仅已投递弹体继续飞行。
