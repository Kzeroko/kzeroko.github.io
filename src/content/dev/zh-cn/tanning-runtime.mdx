鞣制是每名玩家一个的临时服务端会话：在原版炼药锅旁直接在世界里操作，由 ModernUI 叠加层显示。会话驱动一个纯粹的工序模拟，每刻把状态推送给鞣匠；不保存任何数据，批次提交前也不会拿走玩家任何东西。以下是 `internal.tanning` 下的内部约定，不是公开 API 门面。

## 它做什么

系统为每名鞣匠维护一个批次、每口缸只允许一名鞣匠：开工、模拟六道工序、判定带时机的输入，再把结果变成皮革。玩家规则见[皮革鞣制](/zh-cn/wiki/tanning/)，JSON 见[鞣制配方数据](/zh-cn/wiki/tanning-recipes/)。

它刻意止步于炼药锅本身的状态。没有方块实体，也没有存档数据：服务器关闭、断线或走开都会丢弃这一批；因为什么都还没消耗，这样做是安全的。皮革的用途、交易和技艺加成都不归它管，完成事件就是扩展点。

## 运行时模型

| 包 | 职责 |
| --- | --- |
| `internal.tanning` | 不含 Minecraft 类型的领域枚举：品级、工序、工具、色调、难度、火、空气。 |
| `internal.tanning.work` | 工序模拟，同样不含 Minecraft 类型，所以 `tools/tanning/TanningWorkCheck.java` 能用机器人来玩它。 |
| `internal.tanning.station` | 作为鞣制缸的炼药锅、背包中的工具与材料、配方查询和标签。 |
| `internal.tanning.session` | 会话、提交、世界效果，以及使用和攻击回调。 |
| `client.tanning` | 客户端眼中自己的批次、它的时钟、鞣制缸预览和世界内输入。 |
| `client.render.hudoverlay.tanning` | 叠加层窗口和精灵图集类。 |

`TanningSystem.initCommon` 注册会话计时器，以及服务端的 `UseBlockCallback` 和 `AttackBlockCallback`。主手拿着 `TanningToolItem` 或匹配的皮料，对 `TanningVat.isVat` 认可的炼药锅使用时，会调用 `TanningSessions.begin`：依次检查水、缸是否被占用、配方、鞣匠圆刀、鞣料和手中皮料数量，然后按手中这一叠确定批次大小。潜行时走速成路线：先 `finishSteadily`，紧接着提交。

`END_SERVER_TICK` 逐个校验会话，推进它的 `TanningWork`，把提示事件作为原版声音和粒子在缸边播放，并发送 `TanningStatePacket.Work`。玩家死亡、处于旁观模式、换了维度或离缸中心超过 8 格，缸不再是炼药锅，或者缸里没水，会话都会关闭。

### 工序阶段

`TanningWork` 把每道工序分为开场、进行、收尾三个阶段。没有热源时跳过烟熏；烟熏开始时读取热源，晾干开始时读取空气。

| 阶段 | 刻数 | 输入 |
| --- | --- | --- |
| `INTRO` | 14（0.7 秒） | 忽略；工序进入进行阶段时才应用按住状态。 |
| `ACTIVE` | 直到工序完成或超时 | 判定。 |
| `OUTRO` | 12（0.6 秒） | 忽略。 |
| `DONE` | — | 会话在同一刻提交。 |

### 数据包

| 通道 | 方向 | 内容 |
| --- | --- | --- |
| `isekaiexpansion:tanning_action` | 客户端 → 服务端 | 会话 ID、`WORK` / `LIFT` / `HOLD`、玩家看到的工序刻，以及按住状态。 |
| `isekaiexpansion:tanning_state` | 服务端 → 客户端 | 会话 ID、模式和提示。`BEGIN` 带鞣制缸、皮料、件数、色调、两项品级上限、难度和整饰工序；`WORKING` 带工序视图、各工序分数、工艺分、提示事件、热源和空气；`RESULT` 带皮革、品级和分数；`CLOSED` 带关闭原因。 |

会话 ID 不符或来自其他维度的操作一律忽略。

### 判定时机

计量条、刀刃和扫线都是 `TanningMotion` 中关于工序进行刻数和种子的纯函数。客户端以最近一次服务端刻加上经过的时间来绘制它们，最多外推 2 刻，并在 `WORK` 和 `LIFT` 里报告同一个带小数的刻。

服务端在报告的刻上判定带时机的操作，并把它限制在 `[now − lag, now]` 内，其中 `lag = 2 + ceil(ping / 50)` 刻，上限 12。客户端要等服务端通过工序的操作序号确认上一次操作，或等待 450 毫秒，才会发送下一次操作，并且两次之间至少间隔 140 毫秒。

### 输入与叠加层

准星对着本会话的鞣制缸时，`TanningInputClient` 用 `ClientPreAttackCallback` 截获攻击键：点击数大于零时发送一次 `WORK`，按住也不会开始挖掘方块。客户端的 `UseBlockCallback` 在使用键刚按下时发送 `LIFT` 并返回 `FAIL`；潜行时例外，这次交互会送到服务端，触发稳妥完成。按住使用键的状态每个客户端刻轮询一次，只在变化时以 `HOLD` 发送。服务端对鞣匠自己的鞣制缸，在 `AttackBlockCallback` 里同样返回 `FAIL`。

`TanningHudOverlay` 挂载一个不可聚焦的 ModernUI 根视图，向 `HudAPI` 注册，并在每个客户端刻送达一个 `TanningHudPresentation`：预览、进行中、结果或隐藏。预览完全在客户端根据已同步的配方、世界和玩家背包计算。结果会显示 5 秒。

## 约定

- **提交前不拿任何东西**。`TanningCommit` 先检查水和鞣匠圆刀，再把批次缩小到仍然携带的皮料和鞣料能做的件数，然后要么全部拿走，要么一样不拿。不在 `#minecraft:logs` 里的鞣料优先消耗。
- **提交顺序**。拿走皮料和鞣料，取用一格水，非创造模式下用到的工具各消耗 1 点耐久，执行 `ON_LEATHER_TANNED`，把皮革放进背包或掉落，触发任务计数，最后播放世界效果。
- **品级**。取工艺品级、配方 `max_grade` 和工具上限三者中最低的一个。工具上限只计算开工时携带、提交时仍然携带的工具。
- **匠心之作**。总分达到 97 及以上额外多一件。任务计数按批次件数计算，不含这一件。
- **每人一批**。开新的一批会放下这名玩家之前的批次；别人正在使用的缸会以 `VAT_BUSY` 拒绝。
- **重载**。会话持有自己的配方对象，所以重载不会改变进行中的批次。
- **事件所在线程**。`ON_LEATHER_TANNED` 在服务端线程执行，参数为玩家、配方、最终品级和产物堆叠，回调可以直接修改产物。

## 如何扩展

新增皮料就写配方，新增鞣料就加标签条目。需要在完成时加入内部行为，就在通用初始化阶段注册：

```java
PlayerTanningEvents.ON_LEATHER_TANNED.register((player, recipe, grade, output) -> {
    if (grade == TanningGrade.LEGENDARY) {
        output.getOrCreateNbt().putBoolean("example_royal", true);
    }
});
```

`work` 包里不要引入 Minecraft 类型：调参工具不加载游戏就要编译它。改动任何一道工序、`TanningDifficulty` 或品级阈值后，都要运行调参工具，让结果表保持在预期区间内。

## 验证

在仓库根目录运行机器人调参工具。它为每种机器人和每个难度各模拟 1500 批；完美鞣匠拿不到传说、稳妥完成不是优良、放着不管的批次不是普通，或者有批次无法结束，都会判定失败。

```bash
./gradlew.bat -I tools/tanning/verify.gradle checkTanningWork --offline
```

游戏内：

- 分别用手持皮料、潜行速成和只拿工具的方式开工；检查缸里没水、缺少圆刀和缺少鞣料时的提示。
- 完成每道工序，确认攻击从不会打碎缸、使用键每道工序只提起一次、挡板跟随按住的按键。
- 批次进行中走开、打掉缸、舀空水，确认没有消耗任何东西。
- 批次进行中把皮料收起来，确认批次是缩小而不是失败。
- 分别在有火和无火、下雨和晴天、少带某件工具的情况下完成，对照叠加层显示的上限和结果。
- 让第二名玩家使用同一口缸，确认出现 `VAT_BUSY`。
