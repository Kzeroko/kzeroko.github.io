NPC 战斗由 `entity.CombatNpcEntity` 与内部的 `internal.ai.action` 实现负责。这些类型供项目内部扩展，不是公开战斗门面。本页说明自主行动的 NPC；玩家控制的变身仍使用玩家的战斗输入。

## 它做什么

战斗 NPC 通过威胁传感器选择目标。`NpcCombatController` 调度法术与支援动作，`NpcWeaponMeleeController` 则在 `supportsNpcCombat()` 与 `NpcConfig.normalMeleeAttacks()` 允许时持续驱动武器近战。普通近战没有动作索引、编写的执行时序或额外冷却；特殊动作冷却期间仍可挥击。

Better Combat 与 Better Mob Combat 是外部依赖。本模组调用它们的武器注册表、就绪检查、攻击范围与起手接口，不在这里定义其武器 JSON 默认值。本地兼容层还会将 `BaseNpcEntity` 和 `SimpleCloneEntity` 的 Better Mob Combat 生物额外冷却替换为 `0`。

## 运行时模型

### 目标意图与保护

`NpcThreatSensor` 在传感器回调中，以 `20` tick 为快速校验间隔、`40` tick 为完整选择间隔。这些是内部扫描门槛，不代表大脑每 tick 都调用此传感器。近期攻击者记忆持续 `600` tick（30 秒），最多保存 `6` 个 UUID；超量时按插入顺序移除首项。刷新已有项只延长有效期，不改变插入位置。未加载、无效或已不允许反击的实体会被移除。

| 意图 | 优先级 | 支援追击距离限制 |
| --- | --- | --- |
| `HOSTILE` | 1 | 无 |
| `FAVOR_HIT` | 2 | 有 |
| `PROTECT` | 3 | 有 |
| `REVENGE` | 4 | 无 |
| `COMMAND` | 5 | 无 |

高优先级意图取代低优先级意图。同级候选通常必须满足 `newDistanceSquared + 1 < oldDistanceSquared`，比较的是距离平方。新的 `FAVOR_HIT` 候选可直接替换另一个协助攻击目标，不要求上述距离优势。指令目标始终通过保护模式的意图检查，但仍须满足目标有效性和伤害限制。

跟随时，`ASSIST` 接受全部普通意图，`DEFEND` 排除 `FAVOR_HIT`，`PASSIVE` 只接受 `REVENGE`。非跟随模式不受这些模式限制。跟随者的常规自卫扫描不会主动选择周围尚未交战的敌对生物；正在攻击 NPC 的生物仍可入选。主动敌对关系由阵营规则决定，NPC 的目标访问器会排除友好阵营实体。

保护对象包括 `protectRange` 内可见的友好玩家与阵营盟友，以及 `max(protectRange, followRange)` 内仍存活的跟随主人；主人无需出现在可见列表中。威胁必须同时接近保护对象和 NPC。令 `A = max(protectRange, aggroRange)`，威胁距保护对象不得超过 `A`，距 NPC 不得超过 `max(followRange, protectRange, aggroRange) + A`。持续支援时仍受这个 NPC 距离限制。

| 保护评分输入 | 数值 |
| --- | --- |
| 阵营盟友 / 友好玩家 / 跟随主人优先级 | 1 / 2 / 3 |
| 优先级乘数 | 1000000 |
| 正在以保护对象为目标的生物 | 10000 |
| 保护对象记录的攻击者 | 9000 |
| 记录的攻击者也正在瞄准保护对象 | 额外 80 |
| 距离扣分 | 减去威胁与保护对象的距离平方 |

`FAVOR_HIT` 要求被跟随或受信任玩家的最近攻击时间有效，且距今不超过 `100` tick（5 秒）。它取玩家攻击的实体，使用相同的距离范围，并按 `priority × 1000000 + 9000 - targetToPlayerSquared - npcToTargetSquared × 0.25` 评分。

当前目标必须存活、同世界、可被选中且符合意图；创造模式和旁观模式玩家被排除。只要目标可见且仍有效，普通仇恨距离检查不会将其清除。不可见的复仇目标可保留至攻击者记忆到期；其他不可见目标必须仍在 `aggroRange` 内。目标变化或可见时更新最后已知位置。追踪不可见目标时使用当前维度内记录的方块位置，没有记录则停留。

### 动作选择与时序

动作集仅根据子类注册内容延迟构建，空动作集也能进行纯武器近战。空白或重复 ID 抛出异常，不再设默认动作索引。客户端与服务端必须按相同顺序注册相同动作。

每次控制器 tick 先递减各动作冷却与正值全局冷却。NPC 死亡、睡眠、使用物品、忙于 POI 或播放表情动作时，会停止导航，并以 `BLOCKED` 结束当前动作。目标效果接管大脑时改为调用 `interrupt()`，不执行控制器 tick，因此该路径不会推进这些冷却。

空闲且全局冷却结束时，控制器逐个评估未冷却动作：满足最低已完成挥击数，选择同世界的存活目标，调用 `isInRange`、`canStart`，并要求评分为有限正数。未启用远程战术时，先比较优先级，再比较评分；完全相同则保留先注册的动作。`rangeOverride()` 为正时替代 `attackRange`，否则使用配置范围。选中的动作预留下一个允许衔接的近战时点：等待期间不发起新挥击，每 tick 重新检查动作资格。

| 字段 | 类型 | 默认值 | 作用 |
| --- | --- | --- | --- |
| `castTicks` | integer | 必填 | CASTING 阶段的非负控制器 tick 数。为零则直接进入 EXECUTING。 |
| `executeTicks` | integer | 必填 | 非负；控制器至少执行 1 tick。 |
| `triggerTick` | integer | 必填 | 从 0 开始的执行 tick，范围为 0 至 `max(0, executeTicks - 1)`；越界抛出异常。 |

`NpcActionTiming.instant()` 为 `(0, 1, 0)`。开始动作时立即调用 `onStart`，执行阶段的处理要等后续控制器 tick。施法的最后一个 tick 切换阶段后直接返回，不在同 tick 触发执行。执行期间，`onTrigger` 在指定 tick 仅调用一次；ATTACK 还会向情绪管理器报告攻击。动作冷却在触发后开始，全局冷却在动作完成或停止时开始。触发前停止也会施加动作冷却，避免被取消的施法每 tick 重试。

控制器保存选定目标的 UUID 与引用。动作进行中检查目标存活、移除状态及世界，以每刻15度的有界转向同步身体、头部和俯仰并追踪目标并推进时序。它**不会**逐 tick 重新执行当前动作的 `selectTarget`、`canStart`、距离、可见性或评分检查。未启用远程战术时，当前动作的 `interruptible()` 为 true 且全局冷却已结束时，更高优先级的合格动作可以在其允许的近战衔接时点抢占；同优先级不能抢占。阻塞、显式中断和目标丢失仍可停止不可抢占动作。

导航锁在开始及施法、执行阶段生效。移动锁只在执行阶段将前进和侧向输入清零，不会重置速度。停止原因为 `FINISHED`、`TARGET_LOST`、`INTERRUPTED`、`BLOCKED`。`onStop` 收到保存的目标（可能为空），随后清除跟踪状态。未启用远程战术时，触发前停止会消耗编写的动作冷却；已施加的动作冷却保留。这些动作计时器不会延迟基础武器攻击。

### 远程战术

`NpcConfig.rangedCombat`启用由战斗控制器统一管理的人形战术，不再设置逃离任务或独占后撤阶段。NPC仅在`attackRange`外接近目标，范围内会先在空闲动作衔接点尝试配置的跃退，再开始下一动作；短促侧步仍可在动作之间进行。未锁定移动的施法可与短促的地面侧步同时进行；路线受阻不会阻塞攻击。伊芙莉娜采用`MAGE`配置，交战范围为16格。

内部实现由`NpcRangedTactics`协调：`NpcTacticalMemory`记录敌方攻击尝试，`NpcTacticalDecision`决定动作排序与时序，`NpcCombatFootwork`处理短促侧步，`NpcCombatLeap`通过共享的`NpcCombatTerrain`几何检查验证跃退轨迹。来袭攻击会刷新压力记忆，但不会延长正在生效的防护或重置防御冷却。目标过近也会形成压力。受压或调整站位时，自动使用物品会等待。

通过动作构建器的`.role(NpcActionRole.QUICK)`指定战术职责，与学派、目标策略和优先级相互独立。远程选择先比较战术评分，再比较编写的优先级与动作评分；进攻候选还须可见。`RECOVERY`的目标生命不高于45%时评分为60，其余情况如下：

| 职责 | 受压 | 平稳且达到偏好距离 | 平稳但距离更近 |
| --- | --- | --- | --- |
| `GENERAL` | 20 | 20 | 20 |
| `QUICK` | 50 | 20 | 20 |
| `CONTROL` | 45 | 15 | 15 |
| `PRESSURE` | 25 | 30 | 30 |
| `COMMITMENT` | 0 | 40 | 5 |
| `RECOVERY` | 10 | 10 | 10 |

默认为`GENERAL`。`QUICK`、`CONTROL`与`RECOVERY`在反击窗口内或敌人过近时使用响应起手与恢复上限，独立法术冷却保持原值。受压时，可中断的非响应动作若仍处于最后承诺刻之前，可让位给已就绪的响应动作；正在执行的`COMMITMENT`则须先达到配置的最低引导时间。远程战术替代仅按优先级抢占的规则，较高优先级的长施法不会挤掉快速施法。伊芙莉娜将火焰与雷击标为`QUICK`、冰系标为`CONTROL`、连射与幽魂剑标为`PRESSURE`、降雨/横扫/光束/终结技标为`COMMITMENT`、治疗标为`RECOVERY`。治疗要求选中目标的生命不高于45%。

允许闪避的远程NPC受击时先尝试安全地面侧步，但锁定移动、起手末段或执行阶段不会闪避。只有找到安全路线，才获得现有战斗翻滚系统提供的短暂伤害规避窗口；否则法师防护可减轻可规避的战斗伤害，并临时增加击退抗性。防护具有固定时长与独立冷却，生效期间不能再开启闪避。环境与穿透伤害遵循共享规避规则。失去控制、死亡或移除时清除当前防御效果；失控与换目标不会清空其恢复成本。防护开启时播放附魔粒子与紫水晶铃音。

侧步尝试六个方向，仅在规划成功后交替偏好侧。近处斜向拉开距离，远处侧移。每条候选走廊按0.35格间距检查已加载区块、世界边界、干燥支撑、身体净空与四角支撑，高差限制为0.6格。不接受缩短敌我距离的落点；从交战范围内出发时，终点也不能超出范围。能看见目标的终点评分更高。每刻移动都会复查下一段并面向目标，同步的侧步标记使客户端躯干保持战斗朝向；失败或超时即释放移动。移动使用速度与碰撞，不瞬移或飞行。近战接近逻辑保持原样，可见目标的路径每4–6个控制器刻刷新。

`NpcRangedCombat`是传给`NpcConfig`构建器的不可变Java配置，不是可重载JSON。省略时使用`DISABLED`，明确使用`MAGE`才会启用。四个配置组均必填且不得为空。下表列出`MAGE`值，`DISABLED`关闭战术及跃退。

| 字段 | 类型 | 默认值 | 范围、单位与用途 |
| --- | --- | --- | --- |
| `enabled` | boolean | true | 启用战术。 |
| `positioning` | Positioning | 必填 | 移动与压力距离。 |
| `defense` | Defense | 必填 | 独立的闪避与防护窗口。 |
| `casting` | Casting | 必填 | 响应节奏与中断处理。 |
| `escape` | Escape | INTENSE | 在空闲选动作前尝试强力拉开距离。 |
| `positioning.dangerDistance` | double | 4 | 正数，单位为格；更近的敌人触发压力与响应节奏。 |
| `positioning.preferredDistance` | double | 9 | 不低于dangerDistance，启用时不得高于attackRange；仅用于评分，不是必须退到的位置。 |
| `positioning.stepDistance` | double | 3.5 | 每条候选路线1–6格。 |
| `positioning.stepSpeed` | double | 0.55 | 大于0且不超过1格/刻。 |
| `positioning.stepTicks` | integer | 12 | 1–30刻，单次移动最长时间。 |
| `positioning.repositionCooldownTicks` | integer | 32 | 不低于stepTicks，规划成功后的冷却。 |
| `positioning.blockedRetryTicks` | integer | 12 | 至少1刻，搜索失败后的重试间隔。 |
| `defense.evadeCooldownTicks` | integer | 36 | 大于evadeInvulnerabilityTicks，成功闪避后的恢复时间。 |
| `defense.evadeInvulnerabilityTicks` | integer | 6 | 非负刻数，可规避伤害的保护窗口。 |
| `defense.guardCooldownTicks` | integer | 65 | 大于guardTicks，从防护开启时计时。 |
| `defense.guardTicks` | integer | 18 | 至少1刻，防护固定持续时间。 |
| `defense.guardedDamageMultiplier` | float | 0.55 | 大于0且不超过1，可规避来袭战斗伤害的倍率。 |
| `defense.guardKnockbackResistance` | double | 0.85 | 0–1，临时加算击退抗性。 |
| `defense.pressureMemoryTicks` | integer | 60 | 至少1刻，敌方攻击后的战术压力记忆。 |
| `defense.counterWindowTicks` | integer | 36 | 1至pressureMemoryTicks，来袭攻击后的响应节奏窗口。 |
| `casting.responseCastTicks` | integer | 10 | 至少1刻，响应动作起手上限。 |
| `casting.responseRecoveryTicks` | integer | 6 | 至少1刻，响应动作全局恢复上限。 |
| `casting.groundGraceTicks` | integer | 10 | 连续离地0–20刻内保留地面起手进度，0关闭宽限。 |
| `casting.interruptedRetryTicks` | integer | 12 | 至少1刻，尚未释放便中断时的动作冷却上限。 |
| `casting.interruptedRecoveryTicks` | integer | 6 | 至少1刻，中断后的全局冷却上限。 |
| `casting.commitmentTicks` | integer | 8 | 非负刻数，起手末段禁止战术抢占与闪避。 |
| `casting.pressureChannelTicks` | integer | 30 | 至少执行1刻，承诺型引导让位前的最低时间。 |

非有限数值和越界值均抛出异常。分别构造四个记录，再传给`new NpcRangedCombat(true, positioning, defense, casting, escape)`，即可独立调整移动、防御与施法。`rangedStatus()`提供压力、响应、防护和移动标记，供调试读取，不暴露可变状态。远程动作未触发便中断时使用短重试冷却；已经释放的法术保留已支付冷却。敌方来袭攻击可将剩余全局恢复缩短到响应上限。


### 跃退强度

原远程任务采用40刻冷却、每扇区8个角度样本、0.35触发比例、0.90偏好半径比例，以及水平1.45、垂直0.28的跃退初速度。现在的`Escape.INTENSE`保留这些触发、半径、初速度和冷却数值，以有界轨迹搜索取代争夺控制权的大脑任务。伊芙莉娜的16格交战范围对应低于5.6格时触发，落点评分偏好14.4格距离。跃退触地后恢复正常地面施法，不会创建飞行或悬停状态。

`NpcCombatLeap`尝试八个均匀方向，每条真实离散轨迹最多追踪24刻，使用0.91水平阻力、0.98垂直阻力和0.08重力。身体沿途每四分之一格检查已加载空间、边界与碰撞；落点复用`NpcCombatTerrain`的支撑检查，至少增加1格敌我距离、保持在交战范围内，高差不超过1.75格。可见性与接近偏好半径的程度决定选择。规划失败时可回退到短促侧步，并立即继续选法术；成功时只设置一次初速度，触地或超时结束。没有独占导航或传送循环，也不会为了跃退取消已开始的动作。

`Escape.MEASURED`使用0.25/0.75比例、0.95水平速度、0.28上抛速度、60刻冷却及15刻重试。`Escape.DISABLED`只关闭强力跃退，保留其他战术。也可直接构造`Escape`，为各NPC调整强度：

| 字段 | 类型 | 默认值 | 范围与含义 |
| --- | --- | --- | --- |
| `escape.enabled` | boolean | true | 在空闲动作衔接点尝试跃退。 |
| `escape.triggerRangeRatio` | double | 0.35 | 大于0且小于desiredRangeRatio，是attackRange的比例。 |
| `escape.desiredRangeRatio` | double | 0.90 | 大于triggerRangeRatio且不超过1，落点评分半径占attackRange的比例。 |
| `escape.horizontalSpeed` | double | 1.45 | 大于0且不超过2格/刻，水平初速度。 |
| `escape.verticalSpeed` | double | 0.28 | 大于0且不超过0.6格/刻，向上初速度。 |
| `escape.cooldownTicks` | integer | 40 | 至少20刻，成功跃退后开始。 |
| `escape.blockedRetryTicks` | integer | 10 | 至少1刻，路线失败后的重试间隔。 |

非有限数值会抛出异常。防护、闪避、短促侧步与跃退各自保留冷却。`rangedStatus()`快照还包含`escaping`标记。

### 支援动作

`NpcSupportSensor` 请求 `20` tick 的感知间隔。可见生物缓存不存在或为空时，会先清空支援列表，不再处理主人。否则，`protectRange` 内存活且受信任的跟随主人排在首位；随后加入范围内可见、友好且非创造/旁观模式的玩家，以及受阵营保护的存活实体，主人不重复添加。

`NpcActions.builder` 默认提供以下目标策略：

| 类型 | 选择方式 |
| --- | --- |
| `ATTACK`、`DEBUFF` | 当前敌对目标 |
| `HEAL` | 自身与支援候选中，受伤存活实体里生命比例最低者；全部满血则无目标 |
| `SHIELD` | 同样优先选择受伤者，没有时选自身 |
| `BUFF` | 随机支援候选；列表为空则选自身 |
| `CLEANSE` | 自身与支援候选中首个存活且带有有害状态效果者 |

控制器校验存活、世界与距离；构造器的默认条件不增加可见性或阵营限制。默认锁定导航但不锁定移动输入，不允许抢占，评分为 `1 + random × 0.001`。生命周期回调默认不执行操作，显式传入的回调函数不得为空。通过 `target`、可组合的 `condition` 与 `score` 可替换选取逻辑、添加战术条件并表达紧急程度；触发时的命中有效性由动作自行校验。

### 持续武器近战

`NpcCombatAttributes`统一定义适配武器的攻击速度基值`4.0`，所有NPC属性构造器均继承它。服务端生成初始化和NBT加载在原版读完保存属性后恢复此基值，不清除装备、服装或效果修饰符。现有原型NPC加载时自动使用正确基准，无须重新生成或执行属性命令；伤害、生命与其他保存属性保留原值。

个体攻击节奏通过属性修饰符调整。直接修改攻击速度基值会在下次生成初始化或加载时被覆盖。这是当前统一的属性规则，不按版本迁移，也不回退到旧数值。

武器就绪时，驱动器像分身近战一样直接调用 `bettermobcombat$startUpswing`。攻击蓄力、连击进度、命中框、动画数据包和武器恢复时间由 Better Mob Combat 负责。此路径不调用延迟起手，不占用调度器执行窗口，也不添加动作结束后的停顿。编写的动作结束后，只要武器恢复时间允许，同一个控制器 tick 即可恢复近战。

启动要求目标存活、可见、同世界且通过 `canAttack`，主手武器具有非空注册攻击列表，并存在当前攻击。`NpcWeaponMeleeController.isInRange` 委托 `MobCombatHelper.isWithinAttackRange`，不会用中心距离排除已相交的命中框。`NpcCombatFacing` 按分身攻击目标的方式对齐朝向与俯仰，俯仰限制为 `-75–75` 度。实际攻击速度必须为有限正数，最终就绪检查仍由依赖负责。

`BetterMobCombatNpcSwingMixin` 在推进待命中的挥击前检查：自主 NPC 未阻塞、不在编写的动作中、不受目标效果接管大脑，且仍在攻击同一个有效目标。取消会清除待命中计时、延迟任务和回调，停止武器动画，但保留已有武器恢复时间。此限定范围的桥接修正了 Better Mob Combat `1.3.1` 取消后仍保留命中倒计时的行为；桥接通过合并后生成的 `@Accessor` 方法访问依赖字段，并调用公开的 `MobAttackWindup`、`PlayerAttackProperties` 接口。它不对其他 mixin 注入的成员声明 shadow，因为 shadow 校验早于这些成员的合并。分身及玩家控制的变身实体不进入该 NPC 桥接。伤害回调还会拒绝无效攻击者、跨世界或死亡/移除的受击者，以及过期的取消令牌。玩家须通过 `canApplyOutgoingDamageToPlayer`，其他存活实体须通过 `canAttack`，随后调用 `tryAttack`。

### 动作穿插策略

每个编写的动作通过 `meleePolicy()` 指定策略。`NpcMeleePolicy.DEFAULT` 等于 `afterSwings(0)`：不要求挥击次数，但等待当前命中时点后再进入动作。

| 策略字段 | 类型 | 默认值 | 含义 |
| --- | --- | --- | --- |
| `transition` | enum | `AFTER_IMPACT` | `AFTER_IMPACT` 等待待执行的命中；`AFTER_RECOVERY` 还等待武器恢复；`INTERRUPT` 取消未完成的挥击。三者都不会清除武器恢复时间。 |
| `minimumSwings` | integer | 0 | 自上一个编写的动作开始以来，已提交的挥击次数。必须非负，负值抛出异常。 |

`NpcMeleePolicy.afterSwings(2)` 要求完成两次挥击后才允许动作。挥空也算完成攻击；一次挥击不论命中多少目标都只计一次，被取消的起手不计数。任何编写的动作开始时都会消耗这份共享计数。敌对目标变化时重置本次交战计数，并使排队中的旧目标伤害失效。状态按 NPC 独立保存，仅在运行时存在，不新增网络或 NBT 字段。

正数门槛明确要求先近战，不应套在必须随时可用的纯远程法术或紧急治疗上；这类动作应设零门槛，并配合优先级、生命或距离条件。中断策略可取消武器起手，但若要替换正在施放的法术，还要求该法术允许 `interruptible()`。所有编写的动作都会在自身持续期间暂停新的基础挥击。快捷物品自动使用会等待命中时点，并要求没有编写的动作正在执行。

### 伤害许可与闪避

玩家敌意按攻击尝试累计，而非只按生命损失累计。普通伤害路径先拒绝无敌、非正伤害和友军伤害，再记录攻击尝试，之后才检查无敌帧与闪避。弹射物穿透回避路径仅在成功回避时记录尝试。

对 `CombatNpcEntity`，来自存活、非创造/旁观模式且可被选中玩家的尝试会刷新 `600` tick（30 秒）记忆。当前传入伤害决定本次用于比较累计次数的门槛：

| 当前潜在伤害 | 所需尝试次数 |
| --- | --- |
| 不超过 2 | 5 |
| 大于 2 且不超过 7 | 2 |
| 大于 7 | 1 |

一旦解锁复仇，状态保留至该玩家记忆到期。不同伤害档位没有独立计数器。敌意表不持久化；NPC 的普通目标和攻击者访问器会隐藏受信任玩家。

对玩家造成的伤害仅允许命中保存的战斗目标，或与该目标玩家同阵营的玩家。没有保存目标时，普通目标必须为玩家，再采用同样规则。创造模式、旁观模式、死亡及其他不可被选中的玩家均被拒绝。`NpcTargetDamageGuard` 会同时检查攻击者与直接来源所归属的 NPC；此限制独立于队伍友军伤害保护。

闪避是通过 `setDodgeableNpc` 明确启用的实体能力。未启用远程战术时，默认闪避要求实体存活、清醒、未使用物品、未骑乘，伤害来源可回避，并符合依赖的空中翻滚许可。它朝远离来源的方向移动，无法确定时向后，叠加翻滚速度并授予翻滚回避窗口。成功闪避设置 `dodgeCooldownTick`，再用刚授予的窗口检查当前伤害。

| 本地闪避计算 | 数值或行为 |
| --- | --- |
| 基础翻滚距离 | `3` 加 Combat Roll 配置增量，最小 `1` |
| 水平速度 | 距离 × `0.475` |
| 水中乘数 | `min(waterHeight, 1) × 0.5` |
| 熔岩乘数 | `0.3` |
| 比草方块更滑的地面 | 乘以草方块与当前地面滑度比的平方 |
| 窗口时长 | Combat Roll 时长 × 速度比，向上取整，最少 `1` tick |
| 速度比限制 | `0.5–2.5`，基准为 `3 × 0.475` |
| 获取依赖时长失败 | 回退为 `8` tick |

本地窗口在到期 tick 仍然有效。绕过无敌或效果的伤害，以及虚空、溺水、饥饿、摔落、窒息和火焰伤害，不能通过此工具回避；可回避伤害还必须有攻击者或直接来源。表中描述的是本地适配，不是外部 Combat Roll 的配置默认值。

## 约定

### 配置与持久化

| 字段 | 类型 | 默认值 | 作用 |
| --- | --- | --- | --- |
| `normalMeleeAttacks` | boolean | true | 仅对具备战斗能力的 NPC 开启持续武器近战。 |
| `attackRange` | double | 2.4 | 默认动作射程及远程站位外边界，单位为格；启用远程配置时不得小于危险距离。 |
| `protectRange` | double | 12 | 保护和支援半径，单位为方块；构造器不限制。 |
| `aggroRange` | double | 12 | 普通敌对及不可见目标范围，单位为方块；构造器不限制。 |
| `dodgeCooldownTick` | integer | 30 | 非远程成功闪避后的冷却；限制为非负。远程闪避使用defense组。 |

多数范围仍是未经校验的配置输入；启用远程战术时，还要求preferredDistance不超过attackRange。表中列出 `NpcConfig` 默认值，具体 NPC 可以覆盖。

战斗冷却字段直接存入实体 NBT：

| 字段 | 类型 | 默认值 | 作用 |
| --- | --- | --- | --- |
| `CombatGlobalCD` | integer | 0 | 剩余特殊动作冷却；加载的负值归 0，不阻止近战。 |
| `CombatActionCD` | list of compounds | 空 | 已知动作 ID 的正值冷却；忽略未知 ID 和非正 tick。 |
| `CombatActionCD[].ActionId` | string | 空 | 精确匹配当前动作集 ID；稳定 ID 可在动作重排后保留冷却对应关系。 |
| `CombatActionCD[].Ticks` | integer | 0 | 剩余正值 tick；重复的有效 ID 后项覆盖前项。 |

控制器不保存动作阶段、已执行时长、捕获目标及是否已触发标记，加载不会续播中断攻击。跟踪器同步动作索引、阶段、序号、目标 UUID、施法开始时间和时长；阶段变化会递增序号。因此两端必须以确定且一致的顺序注册动作。

### 动画归属

普通动作默认使用 `charge_<id>`、接续的 `charge_loop_<id>` 和 `release_<id>`，显式动画键按对应循环或保持标记播放。`usesExternalAnimation()` 可抑制编写动作的 Gecko 动画。持续近战本身不持有 Gecko 动作动画，而由 Better Mob Combat 播放；编写的动作开始时会停止残余武器收势动画，但不会缩短服务端的武器恢复计时。

模型姿态处理末尾、体型塑形之前，`HumanoidPlayerPoseBridge` 先检查已采样的变身宿主姿态。否则，自主 NPC 路径要求 Player Animator 正在播放，普通近战已启用且 Better Mob Combat 战斗动画活跃；屏幕内姿态是例外。躯干、头、四肢分别映射到 `torso`、`head`、`right_arm`、`left_arm`、`right_leg`、`left_leg`，缺少的骨骼被跳过。自主动画通道以已求得的 Gecko 姿态回退，并将弯曲近似为刚体旋转。

手持物品偏移通过矩阵施加：位置除以 `16`，再按 Z/Y/X 顺序旋转，不累积到物品骨骼上。变身的 body 通道使用独立外层矩阵；应用宿主各部位前，桥接器会恢复 Gecko `body` 的绑定变换。扩展渲染器时，应分别处理动画归属与服务器命中权限。

### 地面与空中动作要求

`NpcAction.environment()`与`NpcActions.Builder.environment(...)`选择`GROUND`、`GROUND_OR_WATER`、`WATER`、`AIR`或`ANY`。默认GROUND_OR_WATER要求不在飞行或岩浆中，并且触地或接触水；GROUND严格要求触地且无飞行；WATER要求接触水、无岩浆及飞行；AIR要求离地且不在水或岩浆中；ANY明确允许所有环境。因此伊芙莉娜可在水下施法，而不会启用空中攻击；冰爆仍要求目标站在表面上。选择与执行阶段都检查环境。短暂位移可在配置宽限内暂停远程地面起手，但已经执行的地面/水下法术一旦环境失效仍会停止。连射不可被战术选择抢占，准备反击不会取消其蓄力或射击序列。死亡、失控、目标丢失或环境失效仍会停止动作。

## 扩展方式

在 NPC 子类覆盖 `registerNpcActions(NpcActionSet.Builder)`，保持 ID 稳定、唯一，注册顺序确定。实现 `NpcAction`，或在目标策略合适时使用 `NpcActions.builder`。

| 成员组 | 职责 |
| --- | --- |
| `id`、`type`、`role`、`priority`、`score` | 标识、动作类别及空闲选择顺序 |
| `selectTarget`、`canStart`、`rangeOverride` | 启动许可；命中阶段特有条件须在触发时重查 |
| `timing`、`cooldownTicks`、`globalCooldownTicks` | 时序与两种冷却生命周期 |
| `locksNavigation`、`locksMovement`、`interruptible` | 导航与移动锁，以及是否允许更高优先级动作抢占 |
| `castAnimationKey`、`executeAnimationKey`、`loopCastAnimation`、`holdExecuteAnimation`、`usesExternalAnimation` | 动画归属与播放 |
| `meleePolicy` | 所需挥击数与近战衔接方式 |
| `visualSpell` | 可选法术表现引用 |
| `onStart`、`onTrigger`、`onStop` | 服务器回调；所有停止原因都应释放外部资源 |

动作上下文提供服务器世界、NPC、当前敌对目标、可见生物及支援候选。回调同步执行，控制器不捕获异常进行恢复，应在服务器 tick 路径调用。不要将 `canStart` 通过等同于稍后的命中仍然合法。

构造器生成不可变定义。默认时序为 instant，优先级 `0`，两种特殊动作冷却均为 `0`，范围覆盖为 `0`，无视觉法术、无显式动画键，施法循环为 false，执行保持为 true，外部动画为 false。设置方法拒绝负冷却，以及非有限或负的范围覆盖。重复调用 `condition` 会按短路 AND 组合；再次修改构造器不会改变已生成的动作。

以下示例供已开启普通近战、并具备对应 Gecko 蓄力与释放动画的战斗 NPC 使用：至少两次武器挥击后允许穿插现有雷电法术；冷却尚未结束时会继续挥击。示例动作 ID 需要在该 NPC 上提供对应动画。

```java
builder.add(NpcActions.builder("short_cast_lightning", NpcActionType.ATTACK)
        .timing(NpcActionTiming.of(20, 8, 7))
        .cooldownTicks(22).globalCooldownTicks(22)
        .meleePolicy(NpcMeleePolicy.afterSwings(2))
        .visualSpell(LightningStrikeSpell.INSTANCE)
        .onTrigger((ctx, target) -> LightningStrikeSpell.execute(ctx.npc(), target, 12.0F))
        .build());
```

伊芙莉娜采用此构造器并禁用普通近战；除既有动作外，还使用`NpcPatternActions`施放两种连射、两种降雨与星界终曲，复用玩家弹体和光束逻辑。新原型自行选择循环策略，构造器不会自动将施法者变成近战者。

## 验证

持续受压回归检查覆盖固定防护时长、独立防御冷却、响应职责排序、有界地面起手宽限与释放前中断的重试成本。游戏内应让伊芙莉娜在空地、墙边与悬崖附近面对监守者及多个敌人，核对实际命中节奏、地面释放与可见防御窗口。单元检查不能证明这些遭遇的实战结果。

运行`./gradlew.bat compileJava`。在多人游戏中验证属性存档加载、持久修饰符、武器切换、动作取消和各 NPC 状态独立。

1. 给战斗 NPC 装备已注册近战武器且不注册特殊动作，检查连续挥击节奏；再加入两次挥击后施法的动作，分别检查命中后、恢复后及中断衔接策略。
2. 检查评分完全相同、冷却到期和零施法时长。确认只触发一次，提前取消会消耗动作冷却，特殊动作冷却期间仍继续近战。
3. 起手期间杀死或移除目标、开始使用物品、睡眠、表情动作及目标效果接管，检查各停止路径且无残留依赖起手。
4. 启动自定义动作后，让目标离开范围或移到墙后，确认触发回调执行预期的命中规则。
5. 测试协助、防御、被动模式，以及受信任玩家、阵营盟友和进入挥击范围的旁观者；攻击怪物时不能伤害无关玩家。
6. 测试低、中、高伤害尝试，包含被闪避攻击和记忆到期；被拒绝的友军伤害不得增加敌意次数。
7. 冷却中保存，保留 ID 但重排动作后加载，确认冷却正确对应，且进行中的动作不会续播。
8. 从另一客户端观察近战的基础及替换服装，检查手臂、物品和身体变换没有重复 Gecko 攻击动画；另外验证玩家变身仍由玩家输入控制。
