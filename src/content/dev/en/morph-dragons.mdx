The Saints Dragons bridge runs selected native controllers on the unspawned morph form while the player remains the world entity. This page describes the integration in this repository, checked against the pinned dependency `maven.modrinth:saints-dragons:fe97xyOc`; native ability timings, seat offsets, variants and flight configuration remain owned by Saints Dragons.

## What it does

Common and client bootstraps run only with mod ID `saintsdragons` present and log linkage/runtime failures. Initialisation is sequential, with no rollback of earlier registrations if a later one fails.

The common bridge registers native overrides for both morph ability slots, display IDs, form-skill actions, travel, mounts, tick ownership and variants. Supported runtime species are Raevyx, Stegonaut, Cindervane, Varasuchus, Ignivorus, Volitans, Nulljaw and Atroxiia. The progression species list excludes Nulljaw. These are internal compatibility types, not public facades.

## Runtime model

### One host, selected native ticks

`SaintsDragonMorphLifecycle` binds the native form to its host, clears sitting and initialises animation once. Runtime state is attached to the form; it is not a separately saved dragon. The lifecycle advances at most once per host age tick and preserves native rotation when synchronising host state.

Combat and sound controllers tick on both sides. World effects tick only on the server. The server and owning client advance ability upkeep, animation, flight counters, takeoff locks, dive/water-entry state and flight effort; observers apply replicated visual state before medium-specific smoothing. Scoped native-context mixins permit selected untracked-form methods to advance without changing the world's actual side.

Raevyx, Cindervane, Ignivorus and Volitans have a native flight animation profile, so their flight mode comes from native flight effort rather than from the rider-state evaluator. The owning sides measure effort before synchronising the flight mode; the native effort, mode and wingbeat reads are server-only, so the owning client takes their server branch. Every side then advances the dive pose and the flight blend before banking, pitch and roll, and each species' presentation hook runs last.

Ability displacement of at least 2 blocks (squared distance 4) requests a server teleport. Smaller nontrivial displacement uses player collision movement; changed native velocity copies to the host. The motion epsilon is squared distance `1.0E-8`. This is separate from travel's own movement path.

Detach ends the active native ability, clears input and held bindings, removes attached runtime and unbinds the host. Client breath and storm flags are cleared even when a late observer never received the ability start. It does not save an in-progress native ability for reconnect.

### Travel and landing

All supported dragons handle ordinary travel; only flying dragons support special-travel activation and client prediction. Activation mode is `PRESS`. The handler calls native rider controllers under the host rider context, then transfers native displacement/velocity to the real player. Grounded movement returns a speed override: zero stays zero, otherwise it is the larger of native ridden speed and the form's movement-speed attribute.

Raevyx, Cindervane and Ignivorus share flight/swim/ground dispatch. Volitans has separate flight/swim handling and automatic breach probing. Nulljaw uses its own flight routine. Varasuchus and Atroxiia use dedicated swimming controllers; Stegonaut returns grounded rider speed. Native configuration supplies those speeds and flight impulses.

Takeoff entry checks surface breach, then fall recovery, then ordinary takeoff. Landing or landed recovery blocks activation. A pending request retries for 30 ticks (1.5 seconds), then releases special travel. The fallback touchdown check requires at least 2 aerial ticks and 3 consecutive ground-contact ticks. Landing recovery lasts at least 1 tick, otherwise the native configured cooldown; it stops horizontal and upward velocity, clears input and releases special travel. Water handoff clears takeoff bookkeeping separately.

An already aerial native form can adopt special travel even when the component did not request it. Deactivation requests the native landing sequence; it does not simply zero flight flags. See [client input](/en/dev/morph-client/) for the distinction between press activation and double-tap deactivation.

### Native ability bindings

Morph primary reads the native attack binding; morph secondary reads the native primary binding. They both route through `isekaiexpansion:saints_dragons_native_rider`. Display IDs use the native ability's explicit namespace when present, otherwise `saintsdragons:`; a missing binding displays no ability.

Repeated held-input packets are rejected. A press counts as accepted only if the native callback leaves the requested ability active, including an overlay ability. `HOLD` or a `CANCEL` repress policy requires release. An infinite native section can finish from its own world-time or movement condition and does not imply held input. Named Ignivorus fireball explicitly uses `HOLD`; Summon Storm keeps its native press lifetime.

Accepted native cooldowns have a minimum of 4 ticks (0.2 seconds). A finite cycle sums nonnegative duration sections, counts other sections as 1 tick, and adds recovery. Recovery is the maximum of native cooldown, recovery ticks and interrupt-recovery ticks, with the same minimum. A held/infinite start uses the minimum; release uses recovery.

Repress defaults to `IGNORE`. Raevyx lightning beam, Ignivorus fire breath and Volitans breath use `CANCEL`; Volitans burrow uses `NATIVE`. Cancellation first tries native held release, then force-ends a still-active ability. Native repress calls the native entry point again. Eligible repress can bypass the morph display cooldown.

## Contracts

### Damage and attribution

Native direct, spawned-projectile and ray damage resolve back to the player and originating species/ability. Resolution prefers captured ray/projectile origin before the currently active form ability. Moving native sounds are also redirected to the host entity ID and UUID for tracking viewers and the host.

For positive incoming damage, the bridge computes:

```text
total = nativeAmount × nativeFactor + flatBonus
      + meleePower × meleeFactor + spellPower × spellFactor
```

Nonpositive totals become zero. Exact identity scaling returns the original amount without an added critical roll. Other scaling uses the host's normalised magic critical attributes when spell factor is strictly greater than melee factor, otherwise melee critical attributes. Critical damage multiplies by `1 + max(0, normalisedBonus)`.

Spell power uses the noncritical value of the explicit scaling school, otherwise the species school. Melee power uses live attack damage plus positive additive main-hand item damage suppressed by modular equipment handling. When that item contribution is positive, the current implementation multiplies the **whole sum** by live attack damage divided by base-plus-additive attack damage; a nonpositive denominator/scale falls back to 1. This can apply proportional scaling again to the live portion.

### Upkeep and muzzle origin

Raevyx advances beam energy and beam look. Every 5 server ticks it also advances supercharge, temporary invulnerability and storm-aura upkeep, matching the native cadence. Ignivorus advances fire-breath energy and phase state, with its breath stream ticking on the server. Volitans similarly advances breath-gauge energy and its server breath stream. Varasuchus advances phase-two linger. Other profiles have no extra upkeep/effect override here.

Presentation hooks run on every side. Raevyx and Cindervane advance the tail counter-bank that bends the tail against the bank. Raevyx, Ignivorus and Volitans advance the breath pose that turns the neck toward the breath or beam direction. Ignivorus and Volitans restate the native activity condition because Saints Dragons ticks that pose inline: Ignivorus while breathing fire before Skyfall starts, Volitans while breathing or in its breath intro, but not while burrowing or during the ultimate slam.

Raevyx uses `beamBoneOrigin` and Volitans uses `breathBoneOrigin`. Ignivorus inherits the default null locator, so this bridge neither samples nor applies a client muzzle offset for it. The owning client samples a rendered locator, converts its world offset into body-yaw-local space, and sends only changed quantised samples, no more often than every 2 ticks. Change detection quantises at 256 units per block; the packet still carries floating-point offsets.

The server accepts the sample only for the active matching morph revision and a dragon form, then reprojects it using current position/body yaw before effects. **The receiver does not check finite values or bound the offset's magnitude.** Treat this as the current trust boundary, not server-reconstructed bone geometry. Samples have no age expiry in this runtime; absent samples leave the native fallback in charge.

### Replication

| Packet / state | Fields | Ownership and acceptance |
| --- | --- | --- |
| `saints_dragon_morph_state` | host entity ID, morph revision, raw form type ID, visual state | Host and tracking observers. Only observers apply movement state; both apply new effect inputs. Future matching state can wait; stale revision drops. Apply requires revision and form type match. |
| Visual state | ground move state, flight mode, rider forward/strafe, going up/down, accelerating, flying, takeoff, hovering, landing, rider dive momentum, flight pitch, accumulated roll, dive pose target, flight effort, wingbeat phase, yaw, pitch, body yaw, head yaw | Move/mode are bytes, input, flight values and angles are floats, booleans pack into a flag byte. Reapplied to observer form before native visual smoothing; the flight values are zero for a form without native flight. |
| `saints_dragon_morph_ability_state` | host entity ID, morph revision, active/overlay ability names; empty name means none | Tracking observers and host. Requires active matching revision; no pending queue. Reconciles mismatched local abilities, allowing a short completion window as described below; never starts or seeks one. |
| `saints_dragon_morph_muzzle` | morph revision and local X/Y/Z float offsets | Owning client's C2S sample; checks described above. |

Visual state sends on change and every 20 ticks (1 second). Ability correction sends only when the active/overlay names change. Starting to track sends a visual snapshot only. Therefore an observer joining during an existing ability is not guaranteed its start animation from these packets; the generic preview also has no replay history.

A mismatched registered local ability with more than 40 ticks (2 seconds) left, or an unbounded remaining section, ends immediately. A finite ability within that window can finish naturally: its remaining track time receives 10 extra ticks (0.5 seconds) of grace. The countdown advances after the local ability tick. An empty slot or a changed ability name clears the wait; otherwise expiry forces the end. Matching or unregistered abilities are left alone.

### Passengers, camera and variants

The bridge accepts one real passenger on an adult form when host and rider are alive, nonspectating and not already riding, and the host has no passenger. The synthetic controlling rider remains a separate identity.

Client `passengerLocator` can supply an animated seat; the server uses native species seat offsets, with a separate Nulljaw height path. Dismount probes radii 2.5, 3.5 and 1.8 at angles 0, 30, −30, 60, −60, 90, −90 and 180, passing search depth 10 and clearance parameter 2 to the native radial helper. Carried riders are considered native allies. Passenger orientation uses the native cached rider matrix/spec and seat offsets; absent/stale native data can leave the pose unapplied.

The camera samples the native ride-camera controller only during active morphs. Native client configuration can suppress banking lateral shift; zoom, vertical shift and pitch still come from its output. Generic clipping/perspective rules remain in [morph client presentation](/en/dev/morph-client/).

Variant options and default IDs come from `SaintsDragonVariantRegistry`, for the native `Dragons` catalogue. Applying a variant sets the native texture variant ID. This provider owns form textures, so the generic morph PNG override does not replace them. Selection ownership and persistence remain in [morph lifecycle](/en/dev/morphing/).

## Extending it

Keep species scaling, form-skill bindings, repress policy, upkeep and presentation in its `SaintsDragonProfile`. Register a native action in both the declared power catalogue and species profile. Add movement handling only where the native controller requires it, and keep simulation ownership distinct from render smoothing.

Dependency updates require checking accessor/mixin targets, section and recovery semantics, rider controllers, locator names, sound packets, camera output and seat caches, and any new per-tick native state the species entity tick owns, since a form never runs that tick. The dependency pin identifies the integration target; this page does not assert stable third-party APIs.

The visual packet appends `SaintsDragonMorphEffectState`: breathing (boolean), breath mode (byte), breath intro/fire and storm start world times (longs), storm air-cast and aura (booleans). These server-authored inputs reach the owner as well as observers without overwriting the owner's movement. Volitans and Ignivorus stream particles send the host entity ID; their client factories resolve that host to its rendered dragon form. Ordinary dragon particles keep their original emitter.

Morph controller lookup also works outside the ability tick, so breath particles use the wearer’s interpolated aim. The client retains the rendered mouth in body-local space and resolves it against the current interpolated position and body yaw. It continues to follow the wearer when the model is culled or the camera enters first person. Portrait and shadow passes cannot replace this world sample; native particle travel and collision stay unchanged.

The emission injections specify full overload descriptors. Run `./gradlew.bat -I tools/compat/verify.gradle checkCompat checkPackagedCompat` for dependency signatures, held-input decisions, effect packet round trips and mouth-anchor continuity. The packaged check builds the remapped JAR and checks Saints Dragons injection selectors and invocation targets against the original dependency JAR. It catches selectors that resolve to an overload without the required call. These checks do not start Minecraft or render particles.

## Verifying

Use a dedicated server with owner, existing observer and late observer. Exercise each species on ground, in water, on takeoff, during landing and after teleport. Check recovery locks, momentum, native rotation and absence of double advancement.

For every catalogue action, compare press, hold, release and repress, including release after changing forms. Test overlay plus primary activity and delayed packets. Compare native damage with the coefficient table using known melee/spell attributes, crit disabled, then enabled; include a main-hand weapon while its normal equipment contribution is suppressed.

Check muzzle origin while turning and after delayed/missing reports, inspect malformed-offset handling separately, and verify projectile damage attribution after the original ability ends. Board and dismount one passenger, check friendly-hit rejection, eye/camera obstruction, perspective changes and resource-reloaded native variants.
