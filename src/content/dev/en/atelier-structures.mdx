Atelier captures and places structures as bounded native NBT pieces. Editor jobs run one at a time. Bundled landmarks are generated independently by chunk workers before natural features and structures.

## What it does

Use `/ise dev atelier block` as a creative operator to obtain `isekaiexpansion:atelier_structure_block`. Place the editor outside the selected volume and open it. Its screen uses the existing developer editor framework and theme preferences.

Select `BUNDLED`, `IMPORT` or `EXPORT`, enter the bundle ID and revision, then inspect it. Inspection fills the dimensions and terrain metadata and pins the manifest digest. Changing placement settings requires another inspection. Preview draws the world bounds; placement requires a matching inspected draft.

Capture reads live blocks and typed block entities, including explicit air. Keep the selected area unchanged until capture completes. Capture uses world axes: rotation must be `0`. Actor entities are omitted; a supplied piece containing actors is rejected. Define NPCs and gameplay entities through their owning systems.

### Exchange folders

Paths are relative to Fabric's game directory:

```text
data/isekaiexpansion/atelier/exports/<namespace>/<id path>/<revision>/
data/isekaiexpansion/atelier/imports/<namespace>/<id path>/<revision>/
```

Each revision contains `manifest.json` and its `pieces/` files. The manifest is written last. An incomplete capture cannot be imported. Revision names cannot overwrite an existing export; interrupted captures require a new name.

After editing in Atelier, return a new revision to imports, select `IMPORT`, inspect and place it. To capture changes made in game, keep the same local origin and volume and choose another revision name. The editor retains the inspected revision as the parent when you change its name.

## Runtime model

`AtelierAPI` under `api.atelier` delegates to the internal service. Call it on the server thread after `SERVER_STARTED`. `END_SERVER_TICK` drives jobs. Registry and block access stay on that thread; a single IO worker validates and compresses pieces. The editor packets require a nearby creative operator and reject stale editor versions.

Placement requests a bounded group of chunks, saves original cells and their checksums before mutation, then places the piece. A second pass resolves neighbour states after every piece is present and schedules fluid ticks. There is no full redstone update broadcast. Use the status action to refresh progress.

Recovery lives under `<world>/isekaiexpansion/atelier/jobs/<UUID>/`. `/ise dev atelier pause`, `/ise dev atelier resume <UUID>` and `/ise dev atelier undo <UUID>` operate in the current dimension. Resume replays the original revision with its original before-images; undo restores the recorded cells. World-spawn marker side effects are journaled too; undo restores the prior spawn only when it still matches this job’s result. Undo can overwrite later manual edits inside those cells. Neither operation is a whole-world backup or an entity rollback. Restart pauses interrupted placement; it does not silently replay it.

### Natural landmarks

During KTM2 terrain binding, a landmark selects an unexplored Great Plains centre and saves its ID, revision, digest and coordinates. The reserved build radius covers the complete authored rectangle plus clearance, even with low terrain settings. It avoids the world tree and previous reservations.

`LandmarkGeneration` paints each chunk before `ChunkGenerator.generateFeatures`. `ChunkPieceIndex` indexes intersecting pieces; the writer clips every cell to the current chunk, including negative coordinates and pieces crossing boundaries. It requests no neighboring chunks. A concurrent decoded cache holds at most `262144` cells per landmark. Every intersecting piece is decoded before the chunk is changed. Failed reads or writes stop generation instead of reporting a completed structure. Vanilla chunk postprocessing resolves authored neighbor states and fluids when the surrounding chunks are ready.

`LandmarkTerrainApron` grades the exterior clearance at the end of `NoiseChunkGenerator.buildSurface`, before features in neighbouring chunks can grow across it. A smooth curve joins `site.base - 1` to each natural column, with rounded corners and a soil cap. It changes only the current chunk, leaves authored cells untouched and preserves terrain at and beyond the outer edge. Zero clearance disables grading. This generation pass does not repair already generated terrain.

Natural decoration is excluded from the authored rectangle. `decorationProtection()` leaves the clearance available for vegetation, including chunks wholly inside the margin. `ChunkRegion` guards writes and block-entity access; an exception-safe worker-local guard also blocks direct feature writes. Entity placement, intersecting structures and gameplay protection still use the footprint plus clearance. Structure starts are rejected before references and terrain adaptation; a placement guard covers existing starts.

Natural spawning, chunk population, patrols, structure mobs, reinforcements and jockey spawns are excluded inside protected columns. Commands, spawn eggs, breeding, spawners and authored dungeon `EVENT` spawns remain available. These rules prevent new unmanaged spawns; they do not delete existing mobs or prevent animals from walking into town.

Vanilla chunk status owns generation progress and restart behaviour. The Lucentrystel path queues no placement on player join and does not change player or respawn positions. Remote Sky Garden uses a separate pre-entry preparation path described in [Remote Sky Garden runtime](/en/dev/remote-sky-garden/). `/ise dev atelier landmarks` reports the reserved bounds without loading them. `AtelierAPI.reservedLandmarks(ServerWorld)` returns the same sites as `ReservedLandmark` records: the landmark ID, the authored centre at the saved terrain base, and the placed bounds without clearance. The list is complete as soon as the world has loaded, before any landmark chunk generates; it is empty outside the KTM2 overworld and when no site was reserved. When an authored chunk first loads, the server registers its city profile through `CityAPI`; it does not load the rest of the settlement. `isekaiexpansion:lucentrystel` maps to the `isekaiexpansion:lucentrystel_outpost` profile. Saved resource hashes remain pinned; changed resources fail validation. Flat worlds support manual editing only.

Third-party Arona Layers Gen also decorates chunks as they become live. The optional compatibility hooks apply `AtelierAPI.blocksDecoration` before its direct section writes and plant conversion writes. This preserves authored layers and air inside the footprint while allowing terrain decoration outside it. The hooks are checked against the installed `1.2.2+mc1.20.1` jar; they are enabled only when `aronalayersgen` is loaded.

### Landmark protection

The same immutable footprint and clearance become a protected zone through `LandmarkZoneSource`, which `AtelierSystem.init` registers. The zone covers every height of those columns. Player rules, griefing guards, client prediction and the bypass for creative players with permission level `2` are shared with every other protected place and documented in [protected zones](/en/dev/protected-zones/). The index uses primitive chunk keys. It accepts at most `256` areas and `262144` chunk references, counting overlaps, before allocating the index.

## Contracts

### Bundle manifest

The resource path for shipped revisions is `data/<namespace>/atelier/bundles/<id path>/<revision>/manifest.json`. Piece coordinates share the bundle origin; block coordinates inside each NBT piece start at its own minimum. The editor's origin is its block position plus its origin offset. Rotation applies about that origin.

| Field | Type | Default | What it does |
| --- | --- | --- | --- |
| `schema` | `integer` | required | Must be `2`. |
| `id` | `identifier` | required | Bundle identity, including namespace; path traversal is rejected. |
| `revision` | `string` | required | Immutable name matching `[a-z0-9_-]{1,64}`. |
| `parentRevision` | `string` | required | Previous revision, or empty. |
| `stage` | `string` | required | Release label, at most `128` characters. |
| `min` | `array<integer>` | required | Local XYZ minimum; each coordinate within `-8192…8192`. |
| `size` | `array<integer>` | required | XYZ lengths, each `1–4096`; total volume at most `64000000` cells. Maximum is exclusive. |
| `center` | `array<integer>` | required | Local terrain centre; XZ must lie inside the footprint. |
| `terrainDatum` | `integer` | required | Local Y aligned to the reserved plains surface; must lie inside vertical bounds. |
| `clearance` | `integer` | required | Horizontal protection and terrain-transition margin, `0–256` blocks; vegetation is allowed here and reserved radius covers the expanded rectangle. |
| `pieces` | `array<object>` | required | Nonempty list of at most `8192` disjoint piece boxes. |
| `pieces[].file` | `string` | required | Unique `pieces/[a-z0-9_-]+.nbt` path. |
| `pieces[].pos` | `array<integer>` | required | XYZ offset from the shared bundle origin. |
| `pieces[].size` | `array<integer>` | required | XYZ size, at most `32 × 256 × 32`; must fit bundle bounds. |
| `pieces[].sha256` | `string` | required | Lowercase SHA-256 of the compressed NBT bytes. |
| `pieces[].blocks` | `integer` | required | Explicit cell count, `1–250000`, no larger than piece volume. |

The loader rejects invalid bounds, overlapping boxes, missing files, changed hashes, unknown block IDs or properties and incorrect NBT types. Pieces use Minecraft data version `3465`. Air removes blocks; absent cells leave the destination untouched, as does structure void. Every listed manifest field is required. Unknown keys, including removed arrival fields, are rejected. Bundle, editor draft and landmark state use schema `2`; placement journals use schema `3`; obsolete prototype data has no compatibility reader. Use a new test world for natural generation after this schema change.

Ordinary capture preserves block-entity NBT. Placement applies the configured editor runtime reset; undo bypasses it. Relative gate targets and structure-space regions rotate, as do gate display states and Jigsaw final states. Rotated placements reject unknown mod block-entity adapters and vanilla structure-block payloads before touching the world. With rotation `0`, other payloads remain unchanged except their destination XYZ. Structure-space markers retain their authoring data; bind property spaces through their editor or the structure-space API.

World Gate anchors preserve their authored width, height, colour, audio and channel settings. Their cardinal facing rotates with the block state; the editor NBT processor negates local yaw offsets on a mirror. Portal entity identities are reconstructed from the destination anchor. See [World Gates](/en/dev/world-gates/) for fields and pairing behaviour.

### Server configuration

The `atelier` section belongs to the server's local `IsekaiConfig`. Editor budgets are read while ticking; landmark selection and immutable generation plans are prepared during world binding. Invalid options fail validation instead of being clamped.

| Option | Type | Default | What it does |
| --- | --- | --- | --- |
| `blocksPerTick` | `integer` | `4096` | Editor cell budget per tick, `64–32768`. |
| `millisecondsPerTick` | `integer` | `6` | Cell-loop time budget, `1–15` milliseconds; chunk generation and file commits have their own costs. |
| `generateLandmark` | `boolean` | `true` | Reserve the configured landmark for natural chunk generation; saved reservations remain active. |
| `landmark` | `identifier` | `isekaiexpansion:lucentrystel` | Bundle selected for natural generation. |
| `revision` | `string` | `exterior-v12` | Bundled revision for newly reserved sites; existing sites retain their saved revision. |
| `searchRings` | `integer` | `8` | Search radius in descriptor cells, `1–32`. |
| `resetEditorRuntimeOnPlacement` | `boolean` | `true` | Reset captured dungeon portal IDs, gate progress and opened loot state; keep authored settings. Undo restores original NBT. |

## Extending it

The Lucentrystel path ships `isekaiexpansion:lucentrystel` / `exterior-v12`, labelled `exterior-detailing-work-in-progress`. Its release stage is metadata, not a gameplay completeness check. Existing configuration values are retained; set `atelier.revision=exterior-v12` before creating a new world with an older configuration. Saved landmarks keep their pinned revision and digest. A world pinned to a retired revision requires its original resources in a data pack; changing the default does not upgrade that world.

For a new block entity with relative coordinates, extend `EditorNbtProcessor` and the preflight adapter checks together. Add a round-trip and rotation case to `tools/atelier/dev/AtelierCheck.java`. `AtelierAPI` exposes editor actions, status, landmark bounds, reserved sites, pause, resume and undo; callers should not manage the internal job map directly.

## Verifying

Run the native bundle and recovery contract checks from the mod repository:

```bash
./gradlew.bat -I tools/atelier/verify.gradle checkAtelier assembleLanguageFiles --offline --console=plain
```

Then test the loaded mod in a disposable world: capture a volume with air, inventories and dungeon editors; inspect and place it with each rotation; pause, restart, resume and undo it. Check exact original cells after undo. In a new KTM2 terrain world, verify generation by ordinary exploration, complete chunk seams, protected borders, suppressed natural mobs, city registration and unchanged player arrival. Reopen it and verify that generated chunks and player edits remain intact. The offline suite compares every exterior cell against its chunk index at positive and negative origins, and verifies serial, shuffled and parallel chunk writes with block entities. Test landmark protection with the steps in [protected zones](/en/dev/protected-zones/). These are runtime acceptance procedures; passing the offline task alone does not establish them.
