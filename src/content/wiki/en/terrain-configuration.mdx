Terrain configuration controls placement, geometry, materials and local atmosphere for the KTM2 world generator. Generation takes a server-local snapshot, so editing a live object does not rebuild an existing world or move its saved World Tree.

## Where the files live

Edit the `terrain` object in `config/isekaiexpansion.json`. `autoPatchExoticShaders` is a separate top-level client preference in the same file. These are configuration settings, not namespaced data-pack files; resource-pack priority does not select their values.

The packaged `data/isekaiexpansion/terrain/ktm2.json` is the bundled ReTerraForged preset, read from the mod's classpath. It is not this configuration format or a normal reloadable data-pack override. See the [terrain runtime](/en/dev/terrain-generation/) for that integration.

## Minimal example

This is a fragment to merge into the existing configuration; retain other settings. Missing fields use the declared initial defaults. Avoid explicit null objects.

```json
{
  "terrain": {
    "enabled": true
  },
  "autoPatchExoticShaders": true
}
```

All paths below are relative to `terrain` except the first table. Numeric geometry distances are blocks unless another unit is stated. Finite range checks reject invalid values; they do not clamp them.

## Validation

Block strings accept block-state syntax such as `minecraft:oak_leaves[persistent=true]`. Ordinary surface fields and the exotic rock/top/soil/crystal/weathered/moss/ice/bone/structure/wood fields require non-air, dry, full-cube blocks without block entities. World-tree materials use the less restrictive dry/non-air/no-block-entity rule, except ground also participates in solid surface validation and glow must emit light. Exotic leaves, flowers, vines and fluid have the additional type requirements in their rows.

All numbers checked by the geometry validators must be finite and within range. Family size and vertical scale are checked independently, then combined geometry must still satisfy ring fit and the placement-cell margin. Passing field validation does not guarantee an admitted district: habitat, available height, reserved landmarks and whole-shape checks can reject a candidate.

Palette lists require `1–16` entries with unique IDs per family. Colours are integers `0–16777215`. Setting a family weight or `enabled` to zero/false does not exempt its settings from construction-time validation. Null groups, malformed block states, unsupported skeleton variants or invalid geometry can abort registry/world setup; there is no per-field fallback to silently repair them.

The mod's validators do not report arbitrary unknown JSON keys. A misspelt setting is not a reliable way to detect configuration mistakes. Empty palette lists reject; an empty replacement whitelist is accepted but stops normal district admission.

## Reloading

Set generation options before creating/loading the world, then restart to obtain a fresh registry/generator snapshot. `/reload` is not a terrain regeneration command. Already generated chunks are not rewritten by these paths, and the saved World Tree reservation keeps its coordinates and geometry.

IsekaiCore `0.4.0-build61` supplies login-time synchronisation of the `terrain` object. Generation deliberately reads server-local values; atmosphere reads the active server-synchronised view. This bridge does not live-push edits to connected clients. The separate shader toggle remains local, and shader overlays are prepared when Iris loads a pack; disabling it takes effect on a subsequent pack load.
