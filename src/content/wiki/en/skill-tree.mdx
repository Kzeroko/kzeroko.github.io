The Wheel of Fate is the shared main skill tree, with 379 nodes arranged around Appraisal. Its normal spending limit is 100 points, so choosing routes and a constellation's final power matters more than filling the whole graph.

## What your points buy

| Feature | Current value |
| --- | --- |
| Main category | `isekaiskills:main`, open by default |
| Starting points | 1 |
| Points on a player-level increase | The increase in IsekaiCore level |
| Normal spending limit | 100 |
| Root | Appraisal, costs 1; unlock it yourself |
| Constellations | 7, with 48 nodes each |
| Shared confluence nodes | 42, alongside the root and constellation nodes |

With ordinary progression from level 1, the starting point plus level gains gives a point budget equal to your player level, up to the normal spending limit. Vanilla experience levels do not supply these points. Other point sources or administrator actions can change the stored total.

Appraisal grants `isekaiskills:spassive_appraisal`, a passive marker for integrations. It does not add attributes or implement an inspection overlay itself; what an overlay reveals depends on the integration that consumes the marker.

## Choose a constellation

| Constellation | Primary attribute | Midway passive | Capstones (exclusive) |
| --- | --- | --- | --- |
| Aegis | Constitution | Unbroken Body | World Anchor / Guardian Aegis |
| Warbrand | Strength | Battle Instinct | Colossus Slayer / War God's Echo |
| Gale | Dexterity | Archer's Tempo | Horizon Piercer / Windrunner |
| Moonblade | Technique | Perfect Form | Thousandfold Insight / Bloodless Edge |
| Oracle | Perception | Sixth Sense | Causality Sight / Predator's Certainty |
| Astral | Intelligence | Astral Circuit | Archmage Formula / Mana Sovereign |
| Sanctum | Belief | Merciful Heart | Saint's Covenant / Miracle Weaver |

Each constellation has 5 stages. Within a stage, routes lead from an entry node to a deeper node, then to a weave and the stage gate. A junction accepts **1 incoming route** in the bundled tree; several incoming lines do not mean you must buy every predecessor.

The following gates also require your IsekaiCore player level and points already spent across the **whole category**. The spent-point requirement is checked before buying the node.

| Gate | Player level | Points already spent | Node cost |
| --- | --- | --- | --- |
| Stage 1 | 10 | 8 | 2 |
| Stage 2: midway passive | 20 | 17 | 3 |
| Stage 3 | 35 | 32 | 2 |
| Stage 4 | 50 | 47 | 2 |
| Stage 5 | 70 | 67 | 2 |
| Either capstone | 90 | 82 | 8 |

The capstones of the same constellation exclude each other. Spending in another constellation can satisfy a gate's category-wide spending threshold; it does not replace the incoming route or player-level check.

Confluence nodes connect neighbouring constellations in the table's order, wrapping from Sanctum to Aegis. Their level requirements are 5, 15, 25, 42, 60 and 80, moving outwards. Each costs 2 and adds +1 to each neighbouring primary attribute. These are endpoints: buying one does not open a route into the next constellation.

Buying every available node in a constellation, Appraisal and 1 of its capstones costs 90 points. That is a full-branch total, not the shortest route to the capstone. The entire graph has 764 points of configured costs; excluding 1 capstone per pair leaves 708, well above the normal budget.

| Sanctum | Sanctuary | `isekaiskills:active_sanctuary` |

Each listed power has 3 ranks. Its nodes sit in stages 3, 4 and 5, require player levels 30, 50 and 70, and cost 0 points once the route is available. Repeated unlocks raise the same power's rank.

These powers currently have **no combat effect**. Their configured cooldown and astral-energy cost are both 0; unlocking or placing one on the learned-skill loadout does not give it the attacks, protection or healing suggested by its name. Their rank and loadout integration exist, while their effect bodies are empty.

## Use the skill-tree screen

Open the skill tree with its assigned key. Select a node to see its cost, prerequisites, local condition and exclusions; hold the primary mouse button on an eligible node, or hold Enter or Space, for 1.2 seconds to request an unlock.

| Control or state | Behaviour |
| --- | --- |
| Drag | Pan; moving more than 5 interface units cancels the hold |
| Mouse wheel | Zoom around the pointer |
| Arrow keys | Select a nearby node in that direction |
| Home | Fit the graph |
| `=` / `-` | Zoom in / out |
| Search | Match localised titles and descriptions; cycle through matches |
| Escape or skill-tree key | Close; the skill-tree key does not close while a text field has focus |
| Pending request | Further unlocks wait for the response, up to 5 seconds |

Releasing the button, leaving the graph, losing focus, changing category or losing eligibility cancels an unfinished hold. A completed hold submits a request; the unlock animation waits for the server to show the node as unlocked. A timeout means confirmation was not observed, not that the server rolled the request back.

The screen refreshes its snapshot every 150 milliseconds. It shows inaccessible categories but prevents their unlocks. Race, class and discipline requirements can restrict other categories; they do not make the shared main tree exclusive to a race or class.

## Progression and other systems

| Change | Effect on the tree |
| --- | --- |
| Player level increases | Adds the level difference to the main tree |
| Player level is reverted | Resets main-tree unlocks and sets automatic points to the new level minus 1 |
| Player level is reset | Erases the main category's saved state |
| A requirement stops being met | Blocks a new unlock; this check alone does not revoke an unlocked node |
| Requirement data is reloaded | Server checks use the new data; reconnect to refresh the client's requirement catalogue |
| Learned-skill loadout | Active-power ranks use the same learned-power source and reconcile with loadout changes |
