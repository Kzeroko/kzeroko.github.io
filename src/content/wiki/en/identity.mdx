Your race, class and profession occupy separate identity layers. Progression records the identities you unlock within each layer, so you can return to an unlocked identity without paying its requirements again.

## What is available

| Layer | Layer ID | Bundled graph |
| --- | --- | --- |
| Race | `origins:origin` | Evolution: 11 base identities and 7 advanced dragon branches. |
| Class | `origins-classes:class` | Promotion: 7 disconnected base identities. |
| Profession | `isekaiprofessions:profession` | Promotion: 3 disconnected base identities. |

The race graph has one connected dragon family. Other base races are separate nodes; the class and profession graphs currently offer no connected transition. The interface shows only the connected family containing your current identity.

From `isekaiorigins:dragon`, the bundled branches lead to:

| Target identity | Extra requirements |
| --- | --- |
| `isekaiorigins:raevyx` | None |
| `isekaiorigins:stegonaut` | None |
| `isekaiorigins:cindervane` | None |
| `isekaiorigins:varasuchus` | None |
| `isekaiorigins:ignivorus` | None |
| `isekaiorigins:volitans` | None |
| `isekaiorigins:atroxiia` | None |

These are the bundled graph definitions. A server data pack can replace them and add requirements, so read the node dossier on your server before confirming.

## Opening and using the graph

Use Growth Paths on the status screen to open the race graph, then choose the race, class or profession chapter. Selecting a node shows its description and requirements. Drag the background to pan, use the wheel or zoom controls to zoom, and reset the view to recentre; resetting the view does not erase progress.

| Node state | Meaning |
| --- | --- |
| Current | Your active identity; cannot be activated again. |
| Unlocked | Saved in your history; can be reactivated if still connected and eligible. |
| Available | Prerequisites and current requirements are met; the server checks again when you submit. |
| Locked | The first-unlock conditions are not currently met. |

Hold the primary mouse button on an available or unlocked node. Bundled nodes take 30 ticks (1.5 seconds); packs may choose 10–200 ticks (0.5–10 seconds). Releasing early or moving outside the node cancels. The request is sent as soon as the hold completes, while the button is still down.

The screen does not pause the world. Its server session lasts 1200 ticks (60 seconds); reopening creates a fresh session. A successful server data reload invalidates an open session, so reopen the screen if it reports an expired or invalid request.

## Unlocking and returning

For a first unlock, **every incoming prerequisite** must be your current node or a node already unlocked. The target must have at least one incoming prerequisite. After an unlock, both the identity you left and the chosen identity are recorded.

Returning to a recorded identity skips its prerequisites and costs. It must still be connected to the current identity and permitted by the current server definitions. This allows returning to the base dragon and switching among unlocked dragon branches; it does not let a disconnected class or race be selected.

A node can require these conditions:

| Requirement | What you need | Can it be spent? |
| --- | --- | --- |
| Player level | Isekai Core player level reaches the threshold. | No |
| Experience level | Vanilla experience level reaches the threshold. | Yes, if listed as a cost; levels are removed. |
| Advancement | The named advancement is complete. | No |
| Item | The required registered item is in your inventory in sufficient quantity. | Yes, if listed as a cost. |

All conditions must pass before payment. Creative players skip item quantities and all consumption, but still need required levels and advancements. Revisiting an unlocked node never charges these costs again.

## During the transformation

Acceptance saves the unlock and pays any first-unlock costs before the visual transformation. The normal server timeline is:

| Stage | Timing |
| --- | --- |
| Accepted-node effect | 12 ticks (0.6 seconds) before the transformation begins. |
| Transformation and action lock | 64 ticks (3.2 seconds), following acceptance effects. |
| Identity changes | 26 ticks (1.3 seconds) after transformation begins. |
| Identity reveal | 38 ticks (1.9 seconds) after transformation begins. |
| Complete sequence | 76 ticks (3.8 seconds) from acceptance. |

The screen closes, the camera moves behind the character, and item use, attacks, movement and jumping are locked for the transformation. The previous perspective is restored when the sequence ends if the camera still uses the perspective applied by the sequence.

A disconnect or a target becoming invalid can interrupt the sequence. Already paid costs and recorded unlocks are not rolled back. If the identity had not yet changed, reopen after reconnecting and activate the saved node again once it is eligible; returning does not pay again.

## Other systems

| System | Interaction |
| --- | --- |
| Origin powers | Applying the target changes the identity and reconciles its skill loadout. |
| Morphing | Identity changes reconcile the current morph. The dossier can preview form variations granted by the selected target, but choosing one requires owning that form's morphing power. |
| Saved history | Unlocks survive respawn. A pack rename of a graph/node does not migrate the old history; a removed connection may make an old unlock unreachable. |

Form-variation choices are separate from progression unlocks. Previewing a target or a variation does not grant its identity.

## Where the definitions live

Server graphs live in `data/<namespace>/progression_graphs/<path>.json`. [Progression graph data](/en/wiki/progression-data/) documents every field, prerequisite and reload rule; [Morph data](/en/wiki/morph-data/) covers the powers and forms that an identity can grant.
