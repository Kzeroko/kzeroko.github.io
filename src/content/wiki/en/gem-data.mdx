Gem resources control which bonuses can be rolled and where they fit. The server loads all gem families as one snapshot: an invalid resource keeps the previous snapshot active.

## Where the files live

Except global settings, these paths are relative to `data/<namespace>/`; any namespace can contribute definitions. Global settings are read only from `data/isekaiexpansion/gem_system/settings.json`.

```text
gem_system/settings.json
gem_attributes/random_roll/*.json
gem_attributes/fixed_attributes/*.json
gem_attributes/element_attributes/*.json
gem_attributes/skill_attributes/*.json
socket_profiles/*.json
curses/*.json
gem_consumables/*.json
```

Each file contains one object. A higher-priority pack replaces a resource with the same namespaced path; definitions at different paths are still checked for duplicate IDs, attributes and item ownership. Global settings use the highest resource, not a field-by-field merge. A socket profile's ID is its namespaced path below `socket_profiles/`, without `.json`.

## Minimal example

Save this as `data/example/socket_profiles/iron_sword.json`. It gives an iron sword an unlocked attribute socket and outranks the bundled melee profile. The explicit priority prevents the example being hidden by that existing profile; it is optional to the parser.

```json
{
  "priority": 120,
  "match": {
    "items": [
      "minecraft:iron_sword"
    ]
  },
  "sockets": [
    {
      "kind": "ATTRIBUTE",
      "min_item_level": 0
    }
  ]
}
```

## Fields

Use actual JSON numbers and booleans. Missing required fields or numeric conversion failures reject the reload. Unknown fields are ignored except the explicitly removed keys under Validation. The table calls out intentional fallbacks for wrong container types.

### Global settings

| Field | Type | Default | What it does |
| --- | --- | --- | --- |
| `random_roll_count` | `array<object>` | `[{count:1,weight:80},{count:2,weight:17},{count:3,weight:3}]` | Weighted line counts. Missing, non-array, empty or all-zero-weight lists use this fallback. |
| `random_roll_count[].count` | `integer` | `1` | Positive line count; cannot exceed the number of distinct eligible attributes actually available. |
| `random_roll_count[].weight` | `integer` | `0` | Non-negative; zero entries are removed. |
| `random_requirement_roll` | `object` | `{}` | Controls whether a random gem receives an equipment restriction. |
| `random_requirement_roll.base_chance` | `number` | `0.42` | Finite probability 0–1; used outside a difficulty context and for missing difficulty overrides. |
| `random_requirement_roll.dungeon_difficulty_chances` | `object` | `{}` | Difficulty-to-probability map, finite 0–1. Keys: common, uncommon, rare, epic, legendary, unique. |
| `random_requirement_pool` | `array<object>` | `[]` | Restriction candidates. Empty means no restriction can be rolled. |
| `random_requirement_pool[].id` | `identifier` | required | Unique restriction ID; stored on the gem and used for its translation key. |
| `random_requirement_pool[].weight` | `integer` | `1` | Non-negative default weight. At least this or a difficulty override must be positive. |
| `random_requirement_pool[].dungeon_difficulty_weights` | `object` | `{}` | Same difficulty keys; exact non-negative integer weights override the default. |
| `random_requirement_pool[].match` | `object` | required | At least one constraint is required; all populated groups must match. |
| `random_requirement_pool[].match.items` | `array<item id>` | `[]` | Any listed item; IDs are syntax-checked, not required to exist in the item registry. |
| `random_requirement_pool[].match.all_tags` | `array<tag id>` | `[]` | Every listed item tag must match; leading # is accepted but not required. |
| `random_requirement_pool[].match.any_tags` | `array<tag id>` | `[]` | At least one listed tag must match. |
| `random_requirement_pool[].match.weapon_types` | `array<string>` | `[]` | At least one resolved weapon type; see the complete list below. |
| `random_requirement_pool[].match.nbt` | `array<object>` | `[]` | Every NBT predicate must match. |
| `random_requirement_pool[].match.nbt[].path` | `string` | required | Nonblank dot-separated compound keys; empty segments and list indexing are unsupported. |
| `random_requirement_pool[].match.nbt[].regex` | `string` | required | Valid nonblank regular expression, at most 512 characters. Matches the complete value string; input over 4096 characters never matches. |

| `insert.base_success` | `number` | `0.85` | Finite 0–1, no greater than success_cap. |
| `insert.success_cap` | `number` | `0.95` | Finite 0–1 maximum insertion probability. |
| `insert.crack_chance_on_fail` | `number` | `0.2` | Finite 0–1 probability, rolled only after insertion fails. |
| `insert.fatigue` | `object` | `{}` | Equipment-wide insertion strain; non-object uses defaults. |
| `insert.fatigue.max` | `integer` | `10` | Non-negative stored strain cap. |
| `insert.fatigue.on_fail_add` | `integer` | `1` | Non-negative strain added on a valid failed attempt. |
| `insert.fatigue.on_success_change` | `integer` | `-2` | Non-positive strain change on success; resulting strain clamps to 0–max. |
| `insert.fatigue.success_bonus_curve` | `object` | `{}` | Non-object uses defaults. |
| `insert.fatigue.success_bonus_curve.type` | `enum(LINEAR)` | `LINEAR` | Trimmed and case-insensitive; other curves reject the reload. |
| `insert.fatigue.success_bonus_curve.per_fatigue` | `number` | `0.06` | Finite non-negative probability added per strain point. |

### Consumables

| Field | Type | Default | What it does |
| --- | --- | --- | --- |
| `target` | `enum(EQUIPMENT, GEM, ANY)` | required | EQUIPMENT requires a socket profile and a non-gem item; GEM requires a recognized gem; ANY accepts any nonempty stack. |
| `success_chance` | `number` | `1` | Finite probability 0–1. |
| `consume_rule` | `enum(ALWAYS, ON_SUCCESS, NEVER)` | `ON_SUCCESS` | Consumption after a valid attempt; creative players are exempt. |
| `on_success` | `array<object>` | `[]` | Ordered actions for a successful roll. Missing or non-array means empty. |
| `on_fail` | `array<object>` | `[]` | Ordered actions for a failed roll. At least one branch must contain an action. |
| `on_success[].type / on_fail[].type` | `identifier` | required | Registered action ID from the table below. |

| `data.cracked` | `boolean` | `unchanged` | set_socket_state: changes the crack flag alongside a required lock option; repair_crack removes it directly. |
| `data.kind` | `enum(ATTRIBUTE, FIXED, ELEMENT, SKILL)` | `absent` | reroll_socket_kind: explicit replacement kind, takes precedence over pool; cannot equal current kind. |
| `data.pool` | `array<enum(ATTRIBUTE, FIXED, ELEMENT, SKILL)>` | `all kinds` | reroll_socket_kind: at least 2 distinct kinds if supplied; the current kind is removed before choosing. |
| `data.id` | `identifier` | `random configured curse` | apply_curse: configured curse ID; target must be uncursed. |
| `data.amount` | `integer` | `1` | reduce_insert_fatigue: positive reduction, floored at 0 remaining strain. |

### Enumerations and formulas

Weapon restrictions accept `none`, `sword`, `rapier`, `greatsword`, `glaive`, `dagger`, `lance`, `scythe`, `axe`, `halberd`, `spear`, `mace`, `hammer`, `wand`, `staff`, `katana`, `chakram`, `gauntlet`, `boomerang`, `bow`, `crossbow`, `gun`, `magigun`. Matching ignores case and surrounding whitespace. Unknown names reject the reload.

Formulas produce a multiplier, then the operation's rounding format applies to `base × multiplier`. Variables `areaLv` and `level` both hold area level; `base` and `value` both hold the unscaled attribute value. Formula bands differ from the requirement-map keys:

| Dungeon difficulty | Formula band |
| --- | --- |
| `common`, `uncommon` | `common` |
| `rare`, `epic` | `default` |
| `legendary` | `dangerous` |
| `unique` | `mythic` |

A missing band falls back to `default`. Missing formulas, non-finite results and evaluation errors use multiplier 1; evaluation errors log at use, not reload. The bundled exp4j dependency evaluates formulas. Formula keys and expressions cross the network with limits of 64 and 512 characters respectively; stay within those limits even though loading does not enforce them. Scaling applies to random and fixed attributes, not element or skill gems.

### Consumable actions

All IDs below use the `isekaiexpansion:` namespace. Action fields belong inside `data`.

| Action | Effect |
| --- | --- |
| `isekaiexpansion:reroll_random_lines` | Replace random attributes, values and target requirement. |
| `isekaiexpansion:reroll_random_values` | Keep attributes, operations and requirement; reroll values. |
| `isekaiexpansion:reroll_socketed_random_gems` | Reroll socketed random gems; locked or cracked slots are excluded. |
| `isekaiexpansion:remove_socketed_gem` | Remove with break_chance; a lock blocks removal, a crack does not. |
| `isekaiexpansion:extract_safe` | Remove with zero shatter probability. |
| `isekaiexpansion:set_socket_state` | Change an empty socket's seal after its level unlock. |
| `isekaiexpansion:reroll_socket_kind` | Change an empty, unlocked, uncracked socket to another kind. |
| `isekaiexpansion:apply_curse` | Bind a curse to an uncursed target. |
| `isekaiexpansion:cleanse_curse` | Remove existing curse data. |
| `isekaiexpansion:repair_crack` | Repair a cracked slot whose level requirement is met; a seal is allowed. |
| `isekaiexpansion:reduce_insert_fatigue` | Reduce positive equipment strain. |

Eligibility is checked before rolling and consuming, against both branches. The chosen branch runs in order; successful earlier mutations are not rolled back if a later action does nothing. A successful roll with no applied action does not consume. A failed roll can consume under `ALWAYS` even with an empty failure branch. An empty target is never eligible. Registration alone does not add an eligibility rule for a new code action.

Curse attribute values and status durations scale by the stored multiplier. Incoming damage becomes `damage × (1 + sum(value × curse multiplier))`; status amplifiers do not scale. Multiple curses providing the same effect take the greatest duration and amplifier, combine ambient with OR, and particle/icon visibility with AND.

## Full example

Save this as `data/example/gem_attributes/random_roll/attack_damage.json` after replacing or removing any other active random definition for this attribute. It follows the bundled random files' structure; different filenames do not permit duplicate attribute IDs.

```json
{
  "attribute": "minecraft:generic.attack_damage",
  "domain": "OFFENSE",
  "weight": 1,
  "damage_categories": [
    "MELEE"
  ],
  "operations": [
    {
      "name": "ADDITION",
      "min": 1,
      "max": 2,
      "format": {
        "decimals": 2
      },
      "difficulty_scaling": {
        "formula": "1 + areaLv * 0.02",
        "min_multiplier": 1,
        "max_multiplier": 2
      }
    }
  ]
}
```

## Validation

- **Malformed, empty or non-object file:** records a resource error and rejects the gem snapshot. Required arrays must be nonempty where specified.
- **Unknown registry ID:** gem items, attributes, schools, effects and triggerable skills reject the reload. Profile and requirement item/tag filters validate syntax only; an absent optional-mod item remains a non-match.
- **Duplicate definition:** random attribute IDs, same-family definition IDs, same-family item IDs and cross-family fixed/element/skill item reuse reject the reload. Equal-priority profiles are allowed and sort by ID.
- **Invalid range:** finite, probability and positive checks reject rather than clamp. Some integer fields use numeric conversion; supply integers explicitly. Difficulty weight maps additionally reject fractional values and duplicate keys differing only in case.
- **Removed fields:** `insert.cost_curve` rejects; use `insert.crack_chance_on_fail`. Element `extras` rejects; use typed element fields.
- **Conditional compatibility:** Fabric's `fabric:load_conditions` is checked before gem fields. A failing condition excludes the file; failing settings conditions use defaults. Condition syntax belongs to Fabric. Passing conditions do not relax registry validation.

Unknown action-data keys are normally ignored; `set_socket_state` copies unrecognized keys into saved state. Wrong optional action-data types can bypass readers and fall back rather than fail. JSON action data becomes NBT: booleans become bytes, integral in-range numbers become integers, other numbers become doubles, and null becomes an empty string. Use homogeneous arrays.

A restriction translates as `gem_requirement.<namespace>.<path>`, with path slashes changed to dots. Removing its definition leaves existing gems with that ID unable to match equipment; it does not remove the restriction.

## Reloading

Resources load on the server resource reload. Joining sends the active snapshot; a successful data-pack reload broadcasts it to connected clients. Replacement clears the item-to-profile cache. A gem-local validation failure retains its previous snapshot; this is not a transaction across unrelated reload listeners.

Existing item NBT remains separate. Reloading does not reroll stored random values. It can change compatibility, fixed-definition values and the profile selected for an item. Reducing a profile's socket count can discard excess saved slots when a mutating operation normalizes the item; inspect occupied equipment before making that change.
