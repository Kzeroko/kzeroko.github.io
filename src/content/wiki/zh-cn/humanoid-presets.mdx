玩家预设保存一套可重复使用的外观，角色界面把它作为起点提供给玩家。人形部件目录与它共用同一套外观字段和解锁规则。NPC 的角色外观与衣柜不属于数据：每个 NPC 都在自己的类中声明，详见 [NPC 资源制作](/zh-cn/dev/npc-assets/)。

## 文件位置

| 路径 | 含义 |
| --- | --- |
| `data/<namespace>/humanoid_presets/<path>.json` | 玩家图库预设，ID 为 `<namespace>:<path>`。 |

这些文件属于服务端数据包。模型和纹理属于独立的客户端资源。每个文件声明完整预设，不会作为补丁与其他预设合并。

预设名称使用 `humanoid_preset.<namespace>.<path>`，描述追加 `.desc`。预设路径中的斜杠替换为点。

## 最小示例

将以下玩家图库条目保存为 `data/example/humanoid_presets/simple.json`，其中引用模组自带部件：

```json
{
  "gender": "female",
  "parts": {
    "body": "isekaiexpansion:body/feminine",
    "eyes": "isekaiexpansion:eyes/default"
  },
  "sort": 1000
}
```

## 字段

### 根字段与预设元数据

| 字段 | 类型 | 默认值 | 作用 |
| --- | --- | --- | --- |
| `gender` | `string` | `female` | `female` 或 `male`，忽略首尾空格与大小写；未知值使用默认值。 |
| `age` | `integer` | `18` | 限制为 12–400；属于身份信息，与身高分别设置。 |
| `nickname` | `string` | `""` | 移除格式控制符和控制字符，最多保留48个UTF-16单位且不拆分码点，再去除首尾空格；Unicode控制字符、格式字符与分节符都会移除。非空结果启用昵称。 |
| `preset_name` | `identifier` | `absent` | [姓名池](/zh-cn/wiki/name-pools/)中的可翻译全名ID，最长256字符。与`nickname`互斥；语法无效时拒绝预设。启用姓名显示。 |
| `origin` | `identifier` | `absent` | 种族提示；无效标识符会清空。应用预设时保留玩家实际种族，预设自身的种族不会生效。 |
| `build` | `object` | `neutral` | 体型设置，见下表；未填写的成员使用默认值。 |
| `face` | `object` | `neutral` | 面部设置，见下表；未填写的成员使用默认值。 |
| `palette` | `object` | `channel defaults` | 下表通道的 RGB 颜色；忽略未知通道。 |
| `parts` | `object` | `{}` | 槽位到部件的映射。空对象不会创建模型；玩家验证流程可以补充必需部件。 |
| `parts.<slot>` | `string / object / null` | `absent` | 部件 ID、`{part, style}` 或空部件。槽位及覆盖语义见下文。 |
| `parts.<slot>.part` | `identifier` | `required in object` | 缺失或格式无效时移除此引用；是否存在由后续流程检查。 |
| `parts.<slot>.style` | `string` | `default` | 去除首尾空格并转为小写，只允许 `a-z`、`0-9`、`_`、`-`，最多 64 个字符。无效值改为 `default`。 |
| `sort` | `integer` | `1000` | 图库排序；玩家预设先按此值，再按完整标识符排序。 |
| `tags` | `array<string>` | `[]` | 去除首尾空格并转为小写，移除空项并去重。玩家预设标签须在 48 个字符以内，以便网络同步。 |
| `unlock` | `object` | `always` | 规则元数据，格式见下文；当前预设图库不执行此条件。`type` 为未知值时拒绝该预设。 |

预设允许空对象，此时得到没有显式部件的默认外观。应用完整预设会替换体型、面部、配色和部件，更改性别，并保留玩家年龄、角色姓名与种族。仅应用选定部件类别时，只覆盖对应槽位；身体类别同时复制体型，面部类别同时复制面部参数，且**每次局部应用都会复制整套配色**。

### 体型

| 字段 | 类型 | 默认值 | 作用 |
| --- | --- | --- | --- |
| `build.height` | `number` | `1.8` | 1.20–2.05。身高，单位为格。 |
| `build.torso_width` | `number` | `1` | 0.85–1.20。躯干宽度倍率。 |
| `build.arm_length` | `number` | `1` | 0.90–1.10。手臂长度倍率。 |
| `build.arm_thickness` | `number` | `1` | 0.85–1.15。手臂粗细倍率。 |
| `build.leg_length` | `number` | `1` | 0.90–1.10。腿部长度倍率。 |
| `build.leg_thickness` | `number` | `1` | 0.85–1.15。腿部粗细倍率。 |
| `build.head_scale` | `number` | `1` | 0.90–1.10。头部缩放倍率。 |
| `build.chest_size` | `number` | `1` | 0–2。胸部缩放；允许为零。 |
| `build.chest_lift` | `number` | `0` | -1–1。胸部抬升调整。 |
| `build.chest_spread` | `number` | `0` | -1–1。胸部展开调整。 |

身高及除 `chest_size` 之外的倍率要求为正有限值：零、负数及非有限值恢复默认值，其他值限制到表内范围。`chest_size`、`chest_lift` 和 `chest_spread` 对有限值进行范围限制，非有限值恢复各自默认值。错误的 JSON 类型可能导致整个文件加载失败。

### 面部

| 字段 | 类型 | 默认值 | 作用 |
| --- | --- | --- | --- |
| `face.eye_spacing` | `number` | `0` | -1–1。双眼水平间距。 |
| `face.eye_height` | `number` | `0` | -1–1。眼睛垂直偏移。 |
| `face.eye_depth` | `number` | `0` | -1–1。眼睛深度偏移。 |
| `face.eye_scale` | `number` | `1` | 0.82–1.24。眼睛缩放倍率。 |
| `face.eye_tilt` | `number` | `0` | -1–1。眼睛倾斜调整。 |

带正负号的面部参数限制为 -1–1，非有限值改为 0。眼睛缩放要求为正有限值，否则改为 1。这些参数调整共享骨架，部件需要使用对应骨骼才能显示调整效果。

### 配色

| 字段 | 类型 | 默认值 | 作用 |
| --- | --- | --- | --- |
| `palette.skin` | `RGB` | `#FFFFFF` | `skin` 染色通道：身体与随模组提供的恶魔、龙人、矮人和精灵耳朵共用这一肤色。 |
| `palette.eye_left` | `RGB` | `#4F8FC0` | `eye_left` 染色通道。 |
| `palette.eye_right` | `RGB` | `#4F8FC0` | `eye_right` 染色通道。 |
| `palette.eye_sclera` | `RGB` | `#F6F3EE` | `eye_sclera` 染色通道。 |
| `palette.hair_base` | `RGB` | `#2B2B33` | `hair_base` 染色通道。 |
| `palette.hair_tip` | `RGB` | `#3A3A46` | `hair_tip` 染色通道。 |
| `palette.eyebrow` | `RGB` | `#2B2B33` | `eyebrow` 染色通道。 |
| `palette.lip` | `RGB` | `#C97A78` | `lip` 染色通道。 |
| `palette.blush` | `RGB` | `#E39C96` | `blush` 染色通道。 |
| `palette.trait_primary` | `RGB` | `#FFFFFF` | `trait_primary` 染色通道，由随模组提供的角、尾巴以及猫、狐、机械和鱼人耳朵绑定。整合包中，Mermod 的人鱼尾巴也采用此颜色。 |
| `palette.trait_secondary` | `RGB` | `#CCCCCC` | `trait_secondary` 染色通道，由随模组提供的角、尾巴以及猫、狐、机械和鱼人耳朵绑定。 |
| `palette.outfit_primary` | `RGB` | `#FFFFFF` | `outfit_primary` 染色通道。 |
| `palette.outfit_secondary` | `RGB` | `#FFFFFF` | `outfit_secondary` 染色通道。 |
| `palette.outfit_accent` | `RGB` | `#FFFFFF` | `outfit_accent` 染色通道。 |
| `palette.underwear_primary` | `RGB` | `#FFFFFF` | `underwear_primary` 染色通道。 |
| `palette.underwear_secondary` | `RGB` | `#FFFFFF` | `underwear_secondary` 染色通道。 |
| `palette.accessory_primary` | `RGB` | `#FFFFFF` | `accessory_primary` 染色通道。 |
| `palette.accessory_secondary` | `RGB` | `#CCCCCC` | `accessory_secondary` 染色通道。 |
| `palette.accessory_accent` | `RGB` | `#FFFFFF` | `accessory_accent` 染色通道。 |

颜色接受整数或十六进制字符串，字符串可带 `#` 或 `0x` 前缀；没有前缀的字符串也按十六进制解析。仅保留低 24 位，忽略透明度。缺失通道保留表内默认颜色；显式 null 或无效十六进制文本改为 `#FFFFFF`。颜色字段使用数组或对象可能导致解析失败。

### 部件槽位

| 类别 | 槽位 |
| --- | --- |
| `body` | `body` |
| `face` | `face`, `eyes`, `eyebrows`, `facial_hair` |
| `trait` | `trait_ear`, `trait_horn`, `trait_tail`, `trait_wing`, `trait_other` |
| `hair` | `hair` |
| `underwear` | `underwear_top`, `underwear_bottom` |
| `outfit` | `socks`, `outfit_top`, `outfit_bottom`, `gloves`, `shoes` |
| `accessory` | `ear_accessory`, `face_accessory`, `neck_accessory`, `head_accessory`, `back_accessory` |

槽位名称忽略首尾空格和大小写，未知槽位会被跳过。部件引用可写成标识符字符串，也可写成包含 `part` 与可选 `style` 的对象。预设 JSON 不导入自定义绘制数据。

null、空白字符串、`none`（忽略首尾空格与大小写）或无效部件 ID 会使该槽位为空，包括 `body` 在内的所有槽位都是如此。应用预设时，若种族在某个特征槽有对应特征，验证会把它补入空的特征槽，并为空的 `body` 补上默认身体。

有些部件是链在一起的：同一件衣物分布在多个槽位上，例如默认男性内裤 `isekaiexpansion:underwear_top/default_male` 与 `isekaiexpansion:underwear_bottom/default_male`。预设只写了一个成员时，外观校验会补上其余成员，前提是它们的槽位为空；否则整条链被移除。详见[部件链](/zh-cn/dev/humanoid-parts/)。

标识符格式正确不代表部件、模型或纹理确实存在。找不到指定样式时只尝试 `default`；该样式也不存在时，渲染器跳过此部件。

### 解锁规则

预设与[人形部件](/zh-cn/dev/humanoid-parts/)的 `unlock` 对象使用以下字段：

| 字段 | 类型 | 默认值 | 作用 |
| --- | --- | --- | --- |
| `type` | `enum` | `always` | `always`、`level`、`advancement`、`progression`、`granted`；忽略首尾空格与大小写。其他任何值都会拒绝该文件。 |
| `id` | `identifier` | `absent` | 进度 ID 或成长图 ID；格式错误等同于缺失，对应条件不成立。 |
| `node` | `string` | `""` | 成长图节点；去除首尾空格后须非空，该条件才可能成立。网络限制为 64 个字符。 |
| `level` | `integer` | `0` | 最低冒险者等级；负数改为 0。仅供 `level` 使用。 |

| 规则 | 选择条件 |
| --- | --- |
| `always` | 始终可用；也是 JSON 省略规则时的默认值。 |
| `level` | 玩家在 IsekaiCore 中的冒险者等级达到 `level`；读取等级失败时使用 0。 |
| `advancement` | 服务端存在对应进度，且该玩家已完成。 |
| `progression` | 玩家已解锁成长图 `id` 中的 `node`。 |
| `granted` | 只有记录奖励的系统才能满足。部件与预设没有奖励来源，因此该规则对它们永远不成立；NPC 衣柜换装按玩家的衣柜奖励记录判断。 |

规则只决定玩家何时可以选择，从不决定玩家能否选择。只供 NPC 使用的部件应在部件目录中声明 `"audience": "npc"`，详见[部件制作](/zh-cn/dev/humanoid-parts/)。

当前预设图库不检查预设的 `unlock` 规则，全部已加载预设都会生成可选卡片。提交内容是外观而不是预设 ID，服务端分别验证结果中的各个部件。因此，预设规则不能限制该模板的使用，起作用的是每个部件自身的受众与规则。

## 验证

未知字段会被忽略。字段转换发生异常时整个预设都会被拒绝，未知的 `unlock.type` 与语法无效的 `preset_name` 也是如此。加载器记录该文件错误，并以成功解析的文件替换图库；失败定义不会保留上一版本。缺失的可选字段使用上述默认值。标识符格式检查与目标内容是否存在属于不同步骤。

标签超过 48 个字符或解锁节点超过 64 个字符时，可能成功加载却超过网络写入限制。JSON 加载器并不强制这些长度上限。

`/ise humanoid export player` 会从游戏中的角色写出此格式。导出省略绘制数据，将非默认形状参数四舍五入到 3 位小数，并以十六进制 RGB 输出颜色。

## 重载

服务端数据包重载成功后，在线玩家收到部件目录和预设图库，已保存的外观接受重新验证。客户端模型与纹理需要另行重载。

预设是模板：修改预设不会向所有曾选择它的玩家重新应用。重新验证根据当前部件目录和解锁规则检查已保存外观。
